# 参照資料の台帳

polyisa が参照または使用する外部の仕様書・ソースコード・テストデータ・ツールを、利用条件と許可用途とあわせて一元管理する台帳である。ライセンスや利用条件の情報は本台帳にだけ置き、コード・ISADL 記述・テストからは台帳 ID で参照する。

## 対象と ID の接頭辞

| 接頭辞 | 種類 | 例 |
|---|---|---|
| `SPEC-` | 仕様 | ISA 仕様書、プロセッサマニュアル、ABI 文書、規格 |
| `SRC-` | ソース | 事実確認のために読む一次ソースコード（カーネル UAPI 等） |
| `TEST-` | テスト | テストスイート、テストベクタ、単命令テスト集 |
| `BIN-` | バイナリ | テスト入力として実行する配布物バイナリ |
| `MEAS-` | 計測データ | 公開されている命令実行時間の計測値 |
| `TOOL-` | ツール | 別プロセスとして実行する外部ツール |

本台帳が扱うのは著作権ライセンスと資料に付された利用条件である。特許の扱いは台帳では判断せず、利用条件に特許条項がある場合は備考に明記して所有者が別に判断する。

## 許可用途の記号

| 記号 | 用途 | 内容 |
|---|---|---|
| `R` | 参照 | 読んで理解し、設計・実装判断に使う。本文・図・表・コードは複製しない |
| `F` | 事実の記述 | エンコーディング・定数・構造体配置・数値などの事実を、polyisa 自身の表現（ISADL・Rust 定数表・テスト期待値）で書く |
| `T` | 取得して検証に使う | テスト実行前にローカル（`.testdata/`）へ取得し、入力や期待値として使う。リポジトリには含めない |
| `X` | 実行 | 別プロセスとして実行する |
| `D` | 再配布 | 資料の全部または一部をリポジトリに含める |
| `C` | コードの流用 | ソースコードを複製・移植・翻訳する |

polyisa のライセンスは `MIT OR Apache-2.0` である。BSD 系の資産は原文を確認したうえで `D`・`C` を許可できるが、GPL 系の資産と Arm の機械可読仕様には `D`・`C` を許可しない。

## 運用規則

1. 成果物（コード・ISADL・テスト・文書）に資料の内容を反映する前に、その資料を台帳へ登録する。
2. 用途は利用条件の原文を読み、許容されると確認できた記号だけを許可する。原文から判断できない用途は許可しない。
3. 利用条件の確認は版ごとに行う。参照する版を変更したら再確認する。
4. 台帳に登録された項目はすべて確認済みとして扱い、確認日や確認者の列は持たない。
5. 成果物（`crates/`・`guests/`・`tools/`）から参照するときは機械可読な注記を使う。Rust コード・テストでは `// Ref: SPEC-RISCV-UNPRIV §2.4`（`///`・`//!` も同じ形式）のように ID と節を書き、ライセンス文は書き写さない。
6. 登録前の資料は成果物の用途に使わない（利用条件の確認のために読む場合を除く）。
7. 用途欄は記号のカンマ区切り（例：`R,F`）で書く。`—` はいずれの用途も不許可であることを表す。
8. 開発立ち上げに必須のツール（`TOOL-RUST`・`TOOL-GIT`・`TOOL-CURL`・`TOOL-TASK`・`TOOL-NEXTEST`）は他の項目に先立って登録する。
9. **一次資料の原則**：ISA・ABI の事実（エンコーディング、意味論、定数、構造体配置、動作規則）の根拠は一次資料に限る。ISA の事実は `SPEC-`、ABI の事実は ABI 仕様書と対象 OS 自身の一次ソース（`SRC-LINUX` 等）から取る。他のエミュレータ・アセンブラ・逆アセンブラ・コンパイラ・リンカ（QEMU、binutils、gcc、LLVM、Capstone、Unicorn、Bochs 等の二次実装）を事実の根拠（`R`・`F`）に使わない。二次実装に許される用途は `X`（オラクル実行）と `T`・`BIN`（テスト入力）に限る。仕様書に規定がない事項は二次実装を写さず、設計選択として該当 ISA 文書または [横断的な未実装・暫定課題](known-issues.md) に記録する。

## 機械的な検査（`task refs:check`）

`task refs:check`（`task check` および Git pre-commit フックに含まれる）は次の項目を検査する。表の列構成を変えるときは `tools/devtool` の検査コードも同じ変更で更新する。

1. `crates/`・`guests/`・`tools/` 内の固定書式注記（`Ref:` 等）に現れる ID がすべて台帳に存在する。
2. 参照場所に応じた用途記号が台帳で許可されている。

   | 参照場所 | 必要な用途 |
   |---|---|
   | Rust コード・テスト・ISADL の出典注記（`Ref:`） | `F` |
   | テストデータ取得定義（`tools/testdata/manifest.txt`）と `testkit` 要件表のテストデータ | `T` |
   | `testkit` 要件表のツールと `devtool` が実行する外部ツール | `X` |

3. `.testdata/` が `.gitignore` に含まれ、`git ls-files` に現れない。
4. `guests/*/spec`・`guests/*/src`・`crates/*/src` の Rust ソースに二次実装名（`qemu`・`binutils`・`llvm`・`capstone`・`unicorn`・`bochs`、大文字小文字不問）が含まれていない（規則 9 の検査。ツール要件表の `crates/testkit` と `tests/` は対象外）。
5. 本台帳と `LICENSE-MIT`・`LICENSE-APACHE` を除くファイルに他者の著作権表示（`Copyright`・`©`）や不許可の `SPDX-License-Identifier` が混入していない（`polyisa contributors` と `MIT OR Apache-2.0` のみ許可）。
6. `Cargo.lock` にワークスペース外のパッケージが含まれていない（[ワークスペース構成](architecture/workspace.md)）。

この検査は ID の記載漏れや文章の言い換えまでは自動検出できないため、規則 1・5 の遵守を前提とする。

## 台帳

各列の意味は次のとおりである。

- **ID**：項目を一意に指す識別子（種類接頭辞＋名称）。
- **名称**：資料名・ツール名と識別用の版情報。
- **発行者**：発行組織または個人。
- **版**：利用条件を確認した版。
- **対象**：利用する ISA ファミリ・クレート・作業。
- **利用条件**：ライセンスや利用規約の名称と確認箇所。
- **用途**：許可した用途の記号。
- **備考**：取得元、適用範囲、利用条件上の注意点。
