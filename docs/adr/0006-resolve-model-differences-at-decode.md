# ADR-0006：CPU モデルによる差をデコード時に解決する

- 状態：承認
- 日付：2026-10-26

## 背景

ISA のバージョン、拡張、CPU の世代、ベンダーによる差を表現する（要件 R3）。差には、命令の有無、同じエンコーディングの意味の違い、同じ命令の振る舞いの違いがある（[CPU モデル](../design/cpu-models.md)）。これらを命令の実行のたびに判定すると、インタプリタのすべての命令に分岐が加わる。

CPU モデルの選択には二つの時点が考えられる。一つはビルド時（Cargo の機能フラグや型引数で CPU モデルを固定する）、もう一つは実行時（コマンドラインで選ぶ）である。

## 決定

CPU モデルは実行時に選ぶ。CPU モデルはゲストプロセスの実行中に変わらないので、CPU モデルによる差は、命令をデコードするときに一度だけ解決する。

- 命令の有無とエンコーディングの意味の違いは、デコーダが機能の述語で解決する。
- 命令全体に及ぶ振る舞いの違いは、デコード時に意味論の関数を選ぶことで解決する。
- 意味論の一部にとどまる違いは、意味論が挙動パラメータを読み、IR のバックエンドでは定数として畳み込む。

実行中に変わる CPU 状態のうちデコードと意味論を変えるものは、実行モードとしてブロックキーに含め、同じ規則で解決する。

## 帰結

- 一つのビルドで、すべての CPU モデルを実行時に選べる。利用者は機能の足し引きと挙動パラメータの変更も実行時に行える。
- デコードキャッシュとブロックは CPU モデルに依存するので、CPU モデルの異なるゲストプロセスどうしでは共有できない。現状、一つの実行で使う CPU モデルは一つなので、この制約は問題にならない。
- 挙動パラメータを読む意味論は、インタプリタでは実行時に値を読む。値は実行中に変わらないので分岐の予測が外れにくく、費用は小さいと見込んでいる。

## 検討した代替案

- ビルド時に CPU モデルを固定する：インタプリタのすべての分岐が定数になるが、CPU モデルの数だけビルドが必要になり、実行時の機能の足し引きができない。
- 命令の実行のたびに機能を判定する：実装は単純だが、すべての命令に費用がかかり、JIT でも同じ判定を生成するか、別に解決の仕組みを作る必要がある。
