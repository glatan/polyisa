# ADR-0005：機能の実行とタイミングモデルを分離し、命令イベントで接続する

- 状態：承認
- 日付：2026-10-26

## 背景

タイミングは、全 CPU でサイクル単位の正確さを目標とする（要件 R6）。一方で、実行方式はインタプリタと後の JIT であり、CPU モデルによっては JIT の速度を優先してタイミングを数えない使い方もある。タイミングの計算を命令意味論の中に埋め込むと、CPU モデルごとのタイミングの差が意味論に入り込み、意味論を ISA のバージョンごとに分ける必要が生じる。

## 決定

機能の実行（命令が何をするか）とタイミング（何サイクルかかるか）を分離する（[タイミングモデル](../design/timing.md)）。

- 実行エンジンは、退役した命令ごとに命令イベントを作り、タイミングモデルに渡す。
- タイミングモデルは命令イベントを消費して仮想時間を進める。タイミングモデルから機能の実行への情報は、現在の仮想時間の読み出しに限る。
- 機能の結果に影響する微細構造の性質（MIPS I のロードの遅延スロット、8086 の命令プリフェッチキュー）は、タイミングモデルではなく機能の側で再現する。
- CPU モデルは、タイミングの忠実度（`none`、`cpi`、`exact`、`approx`）を宣言する。

## 帰結

- 命令意味論は、タイミングの手がかりを渡す操作を除いて、タイミングを知らない。同じ意味論を、忠実度の異なる複数の CPU モデルで使える。
- タイミングモデルを無効にした実行に、タイミングの費用がかからない。
- 誤った投機の経路の影響は見えないので、アウトオブオーダー実行の CPU のタイミングは近似になる。この近似は、忠実度 `approx` の誤差の範囲として扱う。
- 時刻を読む命令とシステムコールは、それまでの命令イベントがすべて消費された後の仮想時間を読む必要がある。JIT が命令イベントをバッファに溜める場合も、この順序を守る（[JIT](../design/jit.md)）。

## 検討した代替案

- 命令意味論の中でサイクル数を数える（サイクル単位で状態を進める、8 ビット機のエミュレータで多い方式）：バスのサイクルまで再現する CPU では最も正確だが、意味論が CPU モデルごとに分かれ、JIT との両立が難しい。バスのサイクルまで必要な CPU（68000 など）は、命令イベントを受け取る専用のタイミングモデルとして実装する。
- タイミングモデルが機能の実行を駆動する（実行を待たせる）方式：投機の経路まで再現できるが、機能の実行の構造がタイミングモデルに依存し、インタプリタと JIT の設計が複雑になる。ユーザーモードではタイミングがプログラムの振る舞いを変える経路が時刻の読み出しに限られるので、得られる正確さが費用に見合わない。
