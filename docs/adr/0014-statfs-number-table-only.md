# ADR-0014：statfs 系のシステムコールは番号表だけを持ち、実行しない

- 状態：提案
- 日付：2026-11-10

## 背景

段階 4 の完了条件（[ロードマップ](../design/roadmap.md) の S4-1）は、x86-64 と i386 で busybox のコマンド群を動かすことである。静的リンクの busybox（[参照資料の台帳](../references.md) の BIN-DISTRO 1.35.0）では、`df` がファイルシステムの総量を得るシステムコールに到達する。

番号は Linux の UAPI に由来する。x86_64 は `statfs`（137）と `fstatfs`（138）である。i386 は `statfs`（99）、`fstatfs`（100）、`statfs64`（268）、`fstatfs64`（269）である。

x86_64 では、`df` が BIN-DISTRO 1.35.0 の `statfs`（137）の呼び出しで止まることを確かめた。命令は `mov $0x89,%eax; syscall` であり、アドレスは `0x4ee6e9` である。i386 は番号表だけで、到達経路は確かめていない。

標準ライブラリには、ファイルシステムの総量と空きを可搬に得る関数がない。設計は、この機能の提供元を `host` の FFI 宣言としている（[ホスト抽象化](../design/host.md)）。`host` にはその宣言がない。`cfg(target_*)` と `std::os::` を `host` と `jit` 以外で使うこと、および外部クレートを足すことは禁止されている（[ワークスペース構成](../design/workspace.md)、[ADR-0001](0001-no-external-crates.md)）。

設計（[ワークスペース構成](../design/workspace.md)の「`unsafe` の扱い」）は、`host` の FFI 宣言に `unsafe` を許している。ワークスペースの lint は `unsafe_code = "forbid"` であり、`host` も `#![forbid(unsafe_code)]` を宣言している。FFI 宣言を足すには、`host` でこの lint を緩める変更も要る。

CPU モデルから作る `/proc` のような合成は、仮想カーネルの仕事として設計が置いている。ホストのファイルシステムの量は CPU モデルから導けないので、測らずに固定値で返すことは、この合成には当たらない。

## 決定

statfs 系のシステムコールは、番号表と名前の対応だけを持つ。`host` にファイルシステムの情報を得る手段ができるまで、実行しない。段階 4 の完了条件（S4-1）の対象から `df` を除く。

## 帰結

- S4-1 は、`df` が動くことを完了の条件にしない。対象のアプレットは、台帳で確認した busybox の `busybox --list` が示すものとする。
- 番号と名前は `os-linux` に残し、ABI の突き合わせの対象にする。呼び出しは、処理のないシステムコールと同じく、実行を止める。
- 手段ができたときは、本 ADR を置き換えて実行を足す。

## 検討した代替案

- `host` に statfs の FFI 宣言を足し、システムコールから呼ぶ。設計が定める提供元と一致する。この宣言を足すには、`host` の `unsafe_code` の lint を緩める変更も要る。この ADR では採らない。段階 4 の完了を、その宣言の追加に依存させないためである。
- ホストの `df` の出力をゲストに返す。ホストのコマンドの書式と、ゲストに返す値とが別であり、忠実度を満たさないので採らない。
- 総量と空きを固定値で返す。測っていない容量をゲストに見せるので採らない。
