# ADR-0011：C拡張JR群のwhere句とRV32/RV64重なりの扱い

- 状態：承認
- 日付：2026-11-08

## 背景

RISC-V の C 拡張には、固定ビットだけでは区別できない命令群がある。JR/JALR/MV/ADD/EBREAK（funct3=100・op=10）は `rs1`、`rs2` のゼロ判定で分かれる。RV32 の C.FLW/C.FSW（群）と RV64 の C.LD/C.SD（群）は符号化が同一で、機能集合でのみ区別できる（[参照資料の台帳](../references.md) の SPEC-RISCV-UNPRIV）。

ISADL は `where`（フィールド値の制約）を言語として定めているが（[ISA 記述言語](../design/isa-description.md)）、生成器は未実装だった（[ADR-0002](0002-isa-description-language.md)）。

## 決定

`where` のうちフィールドと定数の等価・非等価の組み合わせを実装する。生成した線形デコーダは、パターンの一致後にフィールドを取り出して条件を評価する。静的検査は次の組を重なりとみなさない。

- 同一フィールドに矛盾する制約を持つ組（例：`rs2 == 0` と `rs2 != 0`）。
- 機能の排他宣言で両立しない `when` の組（例：`rv64` と `rv32`）。

RV32 と RV64 で符号化が同一の命令は、両方を登録し `when`（`rv32`/`rv64`）で区別する。線形デコーダはモデルを見ないので先勝ちで RV64 側を返す。モデル対応の分配は [ADR-0006](0006-resolve-model-differences-at-decode.md) の将来対応とし、現段階の既定（RV64）をコードの注記とテスト（`decode(0x6000, 16) == CLd`）で固定する。

## 帰結

- JR 群の 5 命令と RV32 の単精度ロードストア 4 命令を、符号化の事実どおりに記述できる。
- `where` の一般形（大小比較、複数フィールドの組み合わせ）は未実装のままである。MIPS R6 の割り当て直しのような例が必要になったら、そのときに拡張する。
- デコーダがモデルを見ないのは暫定であり、CPU モデルの切り替えに対応する際はデコーダの入口にモデルを渡す変更が必要になる。

## 検討した代替案

- JR 群を一つの命令にまとめて意味論で分岐する：記述は短いが、命令の一覧と逆アセンブラが仕様書の構成と食い違い、テストの網羅の記録がずれる。
- RV32 側の重なりを登録しない：検証は通るが、RV32 の記述が欠けたままになり、着手条件（[ロードマップ](../design/roadmap.md)）の資料登録と実装がずれる。
