# ADR-0017：ISADL の記述面は Rust で組み立てる `Model` を正規とする

- 状態：承認
- 日付：2026-11-15
- 置き換え：[ADR-0002](0002-isa-description-language.md)（置き換え済み）

## 背景

ADR-0002 は、命令のエンコーディング、オペランド、属性などの静的な性質を ISA 記述言語 ISADL で記述し、`build.rs` で Rust のコードを生成することを決めた。[ISA 記述言語](../design/isa-description.md) は、`.isadl` テキストファイルの文法（`field`、`insn`、`map`、`prefix` など）を定めている。

実装では、テキストの字句解析と構文解析は作られず、各 ISA の記述は `guests/<isa>/spec/*.rs` が `polyisa_isadl::Model` を組み立て、`build.rs` が `include!` する形になった（GAP-0006）。`isagen` は `Model` からデコーダと命令一覧を生成し、`isadl::validate` がデコードの一意性を静的に検査する。S4-2 の時点で、テキスト文法を実装するか、Rust の組み立てを続けるかを決める必要があった。

## 決定

ISADL の記述面は、`guests/<isa>/spec/*.rs` が `polyisa_isadl::Model` を組み立てる Rust の DSL とし、これを正規とする。`.isadl` テキストの字句解析・構文解析は実装しない。

ADR-0002 の目的は変わらず達成される。一つの命令の静的な情報は spec ファイルの一箇所にまとまり、デコーダ、命令一覧、構文の情報は同じ `Model` から生成され、デコードの一意性は生成時に検査される。

テキスト文法は捨てない。設計文書の文法は、外部の道具や Rust 以外の生成元が必要になったときのフロントエンドの設計として残る。その場合も、意味の基準は字句解析の後に検査される `Model` である。

## 帰結

- 言語処理系（字句解析、構文解析、エラー報告）の実装と保守を引き受けなくてよい。spec ファイルの誤りは rustc の型検査で報告される。
- spec ファイルは Rust のコードなので、外部の機械可読な仕様からの変換器を書く場合の出力先は、`.isadl` テキストではなく `Model` を組み立てる Rust のコード（または `Model` を直接構築するバイナリ表現）になる。
- `.isadl` テキストを読む道具は、必要性が生じるまで作らない。

## 検討した代替案

- テキスト文法を実装する：設計文書の文法どおりの字句解析と構文解析は、それ自体が独立した作業になる。現在の Rust DSL は目的とする静的検査をすでに満たしており、記述面を変えても生成物は変わらない。エラー報告の質を専用言語で高める価値はあるが、今の spec の規模（最大は x86min の約 3600 行）では、rustc の診断で足りている。
- `macro_rules!` で記述する：ADR-0002 が棄却した案と同じで、決定木の構築や一意性の検査に向かない。
