# ADR-0002：ISA の静的な性質を ISADL で記述し、`build.rs` で Rust のコードを生成する

- 状態：承認
- 日付：2026-10-26

## 背景

対象の ISA ファミリは 19 あり、各 ISA ファミリが数百から数千の命令と、バージョンと CPU モデルによる差を持つ。命令ごとに、デコーダ、逆アセンブラ、エンコーダ、オペランドの読み書きの情報、命令の属性、タイミング表の項目が必要になる。これらを ISA ごとに手で書くと、同じ命令の情報が複数の箇所に分かれ、片方だけを直す誤りが起こる。

## 決定

命令のエンコーディング、オペランド、レジスタクラス、アセンブリ構文、命令の属性、機能、プロファイル、CPU モデル、挙動パラメータ、タイミング表を、ISA 記述言語 ISADL で記述する（[ISA 記述言語](../design/isa-description.md)）。

命令意味論、ヘルパー、CPU 状態の構造体、ISADL で表せない不規則なデコード処理は Rust で書き、ISADL から名前で参照する。

ゲスト ISA クレートの `build.rs` が `isagen` を呼び、ISADL から Rust のコードを `OUT_DIR` に生成する。生成コードはリポジトリにコミットしない。

## 帰結

- 一つの命令の静的な情報が ISADL の一箇所にまとまり、デコーダ、逆アセンブラ、エンコーダ、メタデータが同じ記述から作られる。デコーダの誤りは逆アセンブラの誤りとしても現れるので、外部の逆アセンブラとの比較で検出できる。
- デコードの一意性を、CPU モデルごとに生成時に検査できる。
- ISADL の言語処理系（構文解析、意味検査、エラーの報告）の実装と保守が必要になる。
- 生成コードがリポジトリにないので、生成コードを読むには `task isagen:dump` を使う。
- `build.rs` の実行の分だけ、ゲスト ISA クレートのビルドが遅くなる。

## 検討した代替案

- 意味論まで記述できる言語（Sail や SLEIGH に相当するもの）を作る：意味論を含めれば、意味論の解析（依存関係の抽出、記号実行）も生成できる。しかし、意味論を書ける言語の設計、型検査、コード生成は、それ自体が大きな作業になる。Rust で書いた意味論をバックエンドに対して総称的にする方法（[ADR-0003](0003-semantics-generic-over-backend.md)）で、インタプリタと JIT の両方に同じ意味論を使う目的は達成できる。
- Rust の宣言的マクロ（`macro_rules!`）で記述する：外部のツールなしで書ける。しかし、決定木の構築やデコードの一意性の検査のような計算はマクロでは困難であり、エラーの報告も読みにくくなる。
- 生成コードをリポジトリにコミットする：差分のレビューで生成結果の変化が見え、`build.rs` の費用がなくなる。しかし、ISADL と生成コードの食い違いを防ぐ検査が別に必要になり、ゲスト ISA ごとに大量の生成コードがリポジトリの差分に現れる。
- 既存の機械可読な仕様（Arm の機械可読な仕様、riscv-opcodes など）から生成する：ISA によっては記述の手間を大きく減らせる。ライセンスが未定の間は外部のデータを取り込まない（[ADR-0009](0009-no-code-reuse-until-license.md)）ので、当面は採らない。ライセンスが決まった後に、ISADL への変換器として改めて検討する。
