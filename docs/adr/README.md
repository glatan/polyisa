## 書き方

ファイル名は `<4 桁の番号>-<判断を表す英語の短い句>.md` とし、番号は追加の順に振る。本文は次の節からなる。

```markdown
# ADR-NNNN：<判断を一文で>

- 状態：提案 | 承認 | 置き換え済み（ADR-MMMM）
- 日付：YYYY-MM-DD

## 背景
判断が必要になった事情と、判断を制約する要件。

## 決定
何を決めたか。

## 帰結
決定によって得るものと、引き受ける費用や制約。

## 検討した代替案
採らなかった案と、採らなかった理由。
```

## 運用の規則

- 承認した ADR の本文は書き換えない。判断を変えるときは新しい ADR を書き、古い ADR の状態を「置き換え済み」にして、新しい ADR の番号を書く。誤字の修正と、リンク先の移動に伴う修正は例外とする。
- 設計文書は ADR の理由を繰り返さず、ADR へのリンクで示す。
- 共通の抽象は段階 4 の終わりまで確定させない（[ロードマップ](../design/roadmap.md)）。それまでの抽象の変更は ADR を必要としない。ただし、この一覧の ADR の決定に反する変更は、段階によらず新しい ADR を必要とする。
