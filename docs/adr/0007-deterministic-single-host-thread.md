# ADR-0007：ゲストスレッドを一つのホストスレッドの上で決定的に多重化する

- 状態：承認
- 日付：2026-10-26

## 背景

仮想カーネル（[ADR-0004](0004-user-mode-virtual-kernel.md)）は、複数のゲストスレッドとゲストプロセスを扱う。ゲストスレッドを複数のホストスレッドで並列に実行すると、複数のコアを使って速くなる。その一方で、次の問題が生じる。

- ゲストのメモリモデルをホストのメモリモデルの上で満たすために、ゲストの不可分操作とフェンスをホストの不可分命令とフェンスへ対応づける必要がある。x86 の TSO のゲストを弱いメモリモデルのホストで動かす場合は、通常のロードとストアにも順序の保証が要る。
- 予約付きロードと条件付きストアを、他のスレッドの書き込みを考慮して正しく実現する必要がある。
- スケジューリングの順序がホストで決まり、実行が決定的でなくなる。サイクル単位のタイミング（要件 R6）とも合わない。

## 決定

当面、すべてのゲストスレッドを一つのホストスレッドの上で実行する。仮想カーネルのスケジューラが、ステップの境界でゲストスレッドを切り替える。次に実行するゲストスレッドは、仮想時間（タイミングが無効なら実行したステップ数）が最も小さいものとし、切り替えの位置を実行予算で決める（[ユーザーモード](../design/user-mode.md)）。

ホストの入出力の待ちは、ゲストの命令を実行しない作業用のホストスレッドに任せる。

## 帰結

- 同じ入力と設定からは、ゲストスレッドの実行の順序が同じになる。
- ゲストから見えるメモリの順序は逐次一貫性になる。これはすべての対象 ISA のメモリモデルが許す振る舞いだが、弱いメモリモデルでしか起こらない並び替えは再現しない（[ゲストメモリ](../design/memory.md)）。
- 予約付きロードと条件付きストアは、スレッドの切り替えで予約を解除するだけで正しく実現できる。
- 複数のゲストスレッドを使うプログラムでも、ホストの 1 コアしか使わない。
- 並列実行を後から導入する場合に備え、意味論の不可分操作は通常のロードとストアと区別して、バックエンドの専用の操作として書く。

## 検討した代替案

- ゲストスレッドごとにホストスレッドを割り当てる（QEMU の MTTCG に近い方式）：性能は高いが、上記の問題をすべて解く必要があり、決定性を失う。決定性を必要としない設定として、仮想カーネルとエンジンが安定した後に、別の ADR で検討する。
