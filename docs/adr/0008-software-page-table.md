# ADR-0008：ゲストのアドレス空間をソフトウェアのページ表で表現する

- 状態：承認
- 日付：2026-10-26

## 背景

QEMU のユーザーモードは、ゲストのアドレス空間をホストのアドレス空間の一部に直接写し、ゲストのアドレスに定数を足すだけでホストのアドレスを得る。この方式は速いが、次の前提を置く。

- ホストのアドレス空間がゲストのアドレス空間より十分に大きい。32 ビットのホストでは 64 ビットのゲストを写せない。
- ゲストのページの保護を、ホストの `mmap` と `mprotect` で表現できる。ホストのページサイズがゲストより大きい場合（Apple Silicon の 16 KiB のページと 4 KiB のページのゲスト）、ページ単位の保護を正しく再現できない。
- ゲストプロセスごとに別のホストプロセスがある。仮想カーネルで一つのホストプロセスに複数のゲストプロセスを置く方式（[ADR-0004](0004-user-mode-virtual-kernel.md)）では、ゲストプロセスごとに異なる写像を同じホストのアドレス空間に置けない。

## 決定

ゲストのアドレス空間は、4 KiB を単位とするソフトウェアのページ表で表現し、ゲストのデータはホストから確保したページフレームに置く（[ゲストメモリ](../design/memory.md)）。vCPU ごとのソフトウェア TLB で、変換の大半を高速経路で済ませる。

## 帰結

- ホストのアドレス空間の大きさ、ページサイズ、OS の写像の機能に依存しない。32 ビットのホストでも 64 ビットのゲストを実行できる。
- 一つのホストプロセスの中に、写像の異なる複数のゲストプロセスを置ける。`fork` はページ表の複製とコピーオンライトで実現できる。
- ページ単位の保護、コピーオンライト、自己書き換えコードの検出を、ホストのシグナルを使わずに実現できる。
- メモリアクセスのたびにソフトウェア TLB の検索が必要になり、直接写す方式より遅い。JIT は検索を機械語に埋め込む（[JIT](../design/jit.md)）。

## 検討した代替案

- ゲストのアドレス空間をホストのアドレス空間に直接写す：アクセスは最も速いが、上記の前提がすべて必要になる。性能上の必要が確認された場合に、64 ビットのホストで一つのゲストプロセスだけを実行する場合の最適化として、別の ADR で検討する。
