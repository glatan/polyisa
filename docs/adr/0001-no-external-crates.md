# ADR-0001：外部クレートに依存しない

- 状態：承認
- 日付：2026-10-26

## 背景

プロジェクトの方針として、依存ライブラリは「これがなければ実装は無茶」と言えるものに限ることになっていた。境界線上の候補として、OS のバインディング（`libc` など）、JIT のコード生成（Cranelift）、テストとベンチマーク専用の開発時依存を検討し、プロジェクトの所有者はいずれも許可しないと決めた。

## 決定

ワークスペースのどのクレートも、ワークスペース外のクレートに依存しない。対象は `dependencies`、`dev-dependencies`、`build-dependencies` のすべてであり、開発作業のためのコマンド（`tools/devtool`）も含む。

標準ライブラリにない機能は自前で実装する。OS の機能で標準ライブラリにないものは、`host` クレートの中で FFI 宣言を自前で書く（[ホスト抽象化](../design/host.md)）。

外部のツールは、別プロセスとして実行するテストのオラクル（clang、llvm-objdump、gdb、wasmtime、QEMU など）と、開発の補助（Task、cargo-nextest など）に限って使ってよい。外部のツールはリンクせず、[参照資料の台帳](../references.md) に登録して使う。オラクルがなくても、ビルドと軽いテストは通る。

## 帰結

- 自前で書くものが増える。主なものは、ISADL の構文解析器、ソフトウェア浮動小数点、ELF の読み込み、JIT のホストのバックエンド、性質テストの実行器、SHA-256、GDB リモートシリアルプロトコル、コマンドラインの引数の解析である。
- 手続きマクロのための構文解析のクレート（`syn` など）を使えないので、コード生成は `build.rs` と自前の言語処理で行う（[ADR-0002](0002-isa-description-language.md)）。
- 依存するクレートの更新、脆弱性の追跡、ライセンスの確認の作業が発生しない。ビルドはネットワークに接続せずに行える。
- FFI 宣言の誤り（構造体の配置や定数の値の誤り）を検出する仕組みを自前で持つ必要がある。`host` クレートのテストで、ホスト上で実際に呼び出して確かめる。

## 検討した代替案

- `libc` クレートを `host` の中だけで使う：多数のホストの構造体と定数が正しく定義されている利点がある。しかし polyisa がホストに求める OS の機能は、標準ライブラリで足りない部分に限ると十数個の関数であり（[ホスト抽象化](../design/host.md) の表）、自前の宣言の保守の費用は小さい。
- JIT に Cranelift を使う：レジスタ割り付けと命令選択の実装を省ける。しかし依存するクレートの数が多く、ゲストの意味論に合わせた最適化（遅延評価のフラグの削除など）を IR の段階で行う必要は変わらない。ホストの命令のエンコーダは、ゲストの ISADL の記述から生成できる。
- テスト専用の依存（性質テストやベンチマークのクレート）を許す：成果物には含まれないが、ビルドに必要なクレートの取得が発生する。必要な機能は擬似乱数と単純な実行器で足りる。
