# ゲストメモリ（`mem`）

`mem` クレートは、ゲストの仮想アドレス空間をホストのアドレス空間へ直接写さず、ソフトウェアのページ表と 4 KiB ページフレームで表現する。

## ソフトウェアページ表を採用する理由

ゲストメモリをホストの `mmap` で直接写す方式（QEMU ユーザーモード等）は高速だが、ホストに十分なアドレス空間があること、ホストのページサイズがゲスト以下であること、1 ホストプロセス＝1 ゲストプロセスであることを前提とする。polyisa は 32 ビットや wasm32 ホストでの 64 ビットゲスト実行、ページサイズの異なるホスト（Apple Silicon の 16 KiB ページ等）、および 1 ホストプロセス内での複数ゲストプロセス・`fork`（コピーオンライト）を扱うため、ソフトウェアページ表を採用している。

## アドレス空間とページフレーム

- **アドレス表現**：メモリは 8 ビットバイト単位、アドレスは `u64` で扱う。32 ビットや 31 ビット ISA のアドレス折り返しは命令意味論側で行う。
- **エンディアン非依存**：ゲストのデータはホストメモリ上に生バイト列として保持し、多バイトの読み書きは常にアクセス属性（`Access`）のエンディアンに従って `from_le_bytes`/`from_be_bytes` で変換する。
- **管理単位**：ページ表は 4 KiB 単位の疎な構造で表現し、64 ビット空間の上位に領域が散らばる ABI（IA-64 等）にも対応する。ゲスト ABI のページサイズが 8 KiB（Alpha・SPARC64）・16 KiB（IA-64・LoongArch）・64 KiB（Power）の場合は 4 KiB の整数倍として扱い、整列と報告（`AT_PAGESZ`）は OS パーソナリティ側で行う。
- **ページフレーム**：4 KiB のホストメモリ片を参照カウント付きで管理し、`fork` 時のアドレス空間複製ではページ表を複製して書き込み許可ページにコピーオンライト印を付け、初回書き込み時に複製する。
- **ページ保護**：読み・書き・実行の許可を持ち、違反時はページフォールト例外を返す。

## アクセス属性（`Access`）

意味論はメモリアクセスごとにデコード時定数の `Access` を指定する。

| 要素 | 値 |
|---|---|
| エンディアン | リトルエンディアン、ビッグエンディアン |
| アライメント | 自然整列を要求（違反はアライメント例外）、要求しない |
| 種類 | データ読み、データ書き、命令フェッチ、不可分 RMW、予約付きロード、条件付きストア |

非整列アクセスがページ境界をまたぐ場合、両ページの許可を先に確認してから読み書きを行い、片側だけ書き込んだ状態でフォールトすることを防ぐ。双エンディアン ISA（Power・ARM・MIPS・SuperH）での実行時切替は実行モードから `Access` へ反映する。

## 不可分操作と予約

polyisa はすべてのゲストスレッドを単一のホストスレッド上でステップ境界ごとに多重化する。この前提のもと、不可分操作は次の形で実現している。

- **RMW・比較交換**：ステップの途中で別スレッドが割り込まないため、通常の読み書きの組として実装できる。
- **予約付きロード／条件付きストア（LL/SC・LR/SC・LDREX/STREX 等）**：vCPU ごとの予約状態として管理し、予約付きロードで設定、条件付きストアの実行またはゲストスレッドの切り替えで解除する。
- **メモリ順序**：ゲストから見える順序は逐次一貫性を満たす。弱いメモリモデル（ARM・Power 等）でしか起こらない並び替えは再現しない。

## ソフトウェア TLB とファイル写像の現状

- **ソフトウェア TLB**：`mem` 内に直接写像キャッシュの型（読み・書き・フェッチ別のタグとホストポインタ）を備えているが、現行の実行ループには未接続である（[GAP-0028](../known-issues.md)）。
- **ファイル裏付け `mmap`**：`MAP_PRIVATE` の遅延読み込み、`MAP_SHARED` のページフレーム共有、`msync`/`munmap`/終了時の書き戻しは `mem` / 仮想カーネルの共通機構としては未着手である（[GAP-0033](../known-issues.md)）。一部 Linux ABI ではファイル内容を事前読み込みする暫定実装を置いている。
