# ユーザーモード

この文書は、ゲストのプログラムに OS のサービスを提供する仕組みを定める。対象は `kernel`、`os-linux`、`os-wasi`、`loader` の各クレートである。ゲストのシステムコールをホストの OS へそのまま渡さず、polyisa のプロセス内の仮想カーネルで実装する理由は [ADR-0004](../adr/0004-user-mode-virtual-kernel.md) にある。

## 構成

OS のサービスは三つの部分に分かれる。

- 仮想カーネル（`kernel`）は、特定の OS に依存しない機構を持つ。ゲストプロセス、ゲストスレッド、スケジューラ、ファイル記述子、仮想ファイルシステム、パイプ、シグナルの保留と配送、futex、時計とタイマーがこれにあたる。
- OS パーソナリティ（`os-linux`、`os-wasi` など）は、特定の OS のシステムコール規約を、仮想カーネルの機構を使って実装する。ゲスト ABI ごとの番号、構造体の配置、定数の値、シグナルフレームの形式もここに置く。
- ローダ（`loader`）は、実行ファイルの形式を解析する。解析の結果をアドレス空間にどう配置するかは OS パーソナリティが決める。

将来の OS パーソナリティとして、PDP-11 の Unix V7、VAX の BSD、ベアメタルのテスト用のセミホスティングを想定している。これらは仮想カーネルの機構を共有し、システムコールの規約だけを実装する。

## ゲスト ABI

ゲスト ABI は、ISA ファミリ、OS パーソナリティ、ABI の変種の三つ組である。三つは独立には選べず、組み合わせごとに番号、構造体、定数の表が決まる。対象とするゲスト ABI は次の表で管理する。表の行がゲスト ABI の単位であり、ゲスト ABI を足すときは行を足す。

| arm | Linux | EABI | ソフトウェア浮動小数点とハードウェア浮動小数点の呼び出し規約の差は ABI 表ではなく ELF の属性で区別する |
| aarch64 | Linux | LP64（リトルエンディアン、ビッグエンディアン） | |
| mips | Linux | o32、n32、n64（両エンディアン） | システムコール番号の基点が変種ごとに異なる |

### ABI 表

Linux のシステムコールの意味は ISA によらずほぼ共通だが、ゲストから見える値はゲスト ABI ごとに異なる。システムコール番号の表、`struct stat` や `struct sigaction` などの構造体の配置、`errno` の値（MIPS、PA-RISC、Alpha、SPARC は他と異なる）、シグナル番号（MIPS、Alpha、SPARC、PA-RISC は他と異なる）、`open` や `mmap` のフラグの値、`ioctl` の番号の符号化、`termios` の配置がこれにあたる。

仮想カーネルは、これらの値を OS パーソナリティ内部の正準の表現で扱う。OS パーソナリティは、ゲスト ABI ごとの表を使って、システムコールの入口で正準の表現へ、出口でゲストの表現へ変換する。表は Rust の定数表として、ゲスト ABI ごとのモジュールに書く。表の値の根拠にする資料（Linux カーネルのソース、ABI の文書）は、台帳で事実の記述（`F`）を許可されたものに限る（[参照資料の台帳](../references.md)）。表の値は、Linux のカーネルの UAPI ヘッダから抽出した値と、テストで突き合わせる（[検証戦略](testing.md)）。この種の値の誤りは、特定のゲスト ABI でだけ、特定のシステムコールが不正な引数で失敗するという形で現れ、原因の特定に時間がかかるからである。

システムコールの呼び出し規約（呼び出しの命令、番号と引数のレジスタ、エラーの返し方）もゲスト ABI ごとに異なる。エラーの返し方は、負の `errno` を返す方式が多いが、MIPS は `a3` レジスタ、Power は CR0 の SO ビット、SPARC はキャリーフラグでエラーを示し、正の `errno` を返す。OS パーソナリティは、ゲスト ABI ごとに引数の取り出しと結果の書き戻しの関数を持つ。

## プロセスとスレッド

ゲストプロセスは、アドレス空間、ファイル記述子の表、シグナルハンドラの表、カレントディレクトリ、資格情報（uid と gid）を持つ。ゲストスレッドは、vCPU、シグナルマスク、スレッド ID を持つ。ゲストプロセスとゲストスレッドは、ホストのプロセスとスレッドには対応しない。

`clone` の各フラグは、新しいゲストスレッドがどの資源を親と共有するかとして解釈する。`fork` はアドレス空間を複製し（[ゲストメモリ](memory.md)）、ファイル記述子の表を複製する。`execve` は、同じゲストプロセスのアドレス空間を新しいイメージで置き換える。実行ファイルの ISA ファミリが元のプロセスと異なる場合は、当面 `ENOEXEC` を返す。`#!` で始まるスクリプトは、仮想カーネルがゲストの名前空間でインタプリタを探して実行する。

## スケジューラ

ゲストスレッドは、一つのホストスレッドの上で、仮想カーネルのスケジューラが多重化する（[ADR-0007](../adr/0007-deterministic-single-host-thread.md)）。スケジューラは、実行可能なゲストスレッドのうち、仮想時間が最も小さいもの（タイミングが無効なら実行したステップ数が最も少ないもの）を選び、決まった実行予算の分だけ実行する。

ゲストスレッドがパイプの読み出しや futex で待つと、スケジューラはそのスレッドを待ち行列に移す。パイプや futex は仮想カーネルの内部の対象なので、待ちの解除も仮想カーネルの中で決まる。

ホストの資源に対する待ち（端末からの入力、ソケット）は、ホストスレッドを止めずに扱う必要がある。仮想カーネルは、ホストの入出力を行う作業用のホストスレッドを持ち、ゲストスレッドの要求をそこへ渡して、完了をイベントとして受け取る。この作業用のスレッドはゲストの命令を実行しないので、ゲストのメモリを同時に触らない。

すべてのゲストスレッドが待ち状態にあり、タイマーとホストの入出力の待ちもない場合、仮想カーネルはデッドロックとして実行を止め、各スレッドの待ちの対象を報告する。すべてのゲストスレッドがタイマーだけを待っている場合は、仮想時間を最も早いタイマーの時刻まで進める。

## 仮想ファイルシステム

仮想カーネルは、ゲストの名前空間でパスを解決する。マウントの表は次のものからなる。

- ゲストのルート：ホストのディレクトリ（ゲストの sysroot）を割り当てる。読み取り専用か、書き込み可能かを選べる。
- `/proc`：プロセスごとの情報（`/proc/self/maps`、`/proc/self/exe` など）と、CPU モデルから作る `/proc/cpuinfo` を、仮想カーネルが合成する。
- `/dev`：`null`、`zero`、`urandom`、`tty` などを仮想カーネルが提供する。
- `/tmp`：設定により、メモリ上のファイルシステムを割り当てる。

シンボリックリンクは仮想カーネルがゲストの名前空間で解決する。ゲストのルートの外を指す絶対パスのリンクや `..` は、ゲストのルートの中で解決し、ホストのファイルシステムのルートへは出ない。動的リンクされたゲストのプログラムは、ゲストのルートにあるゲストの動的リンカとライブラリを使う。

ホストのファイルの読み書きは標準ライブラリの `std::fs` で行う。`stat` の結果は、ホストのメタデータからゲストの `struct stat` に変換する。uid と gid は、設定により、ホストの値をそのまま見せるか、決まった値（たとえば 0）に置き換える。

## ファイル記述子

ファイル記述子が指す対象は、ホストのファイルとディレクトリ、仮想カーネル内のパイプ、ホストのソケット、`eventfd`、`timerfd`、`signalfd`、`epoll`、`memfd`、端末である。`epoll`、`poll`、`select` は、これらの対象の準備状態を仮想カーネルが集めて判定する。

## シグナル

シグナルの保留、マスク、ハンドラの選択、既定の動作は、仮想カーネルの汎用の機構で扱う。シグナルハンドラを呼ぶためのシグナルフレームの構築と、`sigreturn` での復元は、ゲスト ABI ごとの形式で OS パーソナリティが行う。

CPU 例外は、エンジンが返す `GuestException` から、ISA ファミリごとの対応表でシグナルとシグナル情報（`si_code`、`si_addr`）に変換する。遅延スロット内の例外では、ISA ごとの規約（MIPS では分岐命令のアドレスを報告する）に従ってシグナルフレームのプログラムカウンタを決める。

## 時計と乱数

時計は、既定では仮想時間から換算した時刻を返す（[タイミングモデル](timing.md)）。ホストの実時間を使う設定もある。`getrandom`、`/dev/urandom`、ELF の補助ベクタの `AT_RANDOM` は、既定では設定した種から生成する決定的な擬似乱数を返す。

## ローダと初期状態

ローダは ELF（32 ビットと 64 ビット、両エンディアン）と a.out の変種を解析し、ロードするセグメント、エントリポイント、動的リンカのパス、要求する ABI（`e_machine`、`e_flags`、属性セクション）を返す。OS パーソナリティは次の順に初期状態を作る。

1. ELF の情報からゲスト ABI を決める。CPU モデルの ISA ファミリと一致しなければ実行しない。
2. セグメントを、ゲスト ABI のページサイズに整列してアドレス空間に写像する。動的リンカがあれば、それも写像する。
3. 初期スタックに、引数、環境変数、補助ベクタを、ゲスト ABI の規約どおりの配置とアライメントで置く。補助ベクタの `AT_HWCAP`、`AT_HWCAP2`、`AT_PLATFORM` は、CPU モデルの機能から OS パーソナリティの対応表で求める。
4. レジスタを ABI の規約どおりに設定する。

vDSO は最初の段階では提供しない。glibc と musl は、vDSO がなければ時刻の取得などをシステムコールで行う。

## 未実装のシステムコール

未実装のシステムコールは、既定では `ENOSYS` を返し、システムコールの名前と引数を一度だけ報告する。ゲストのプログラムには、新しいシステムコールを試して `ENOSYS` なら古い方法に戻るものが多く、実行を止めるとそれらが動かないからである。厳格な設定では、未実装のシステムコールで実行を止める。この規定は仮想カーネル完成後の動作であり、現試作の `cli` では未対応で実行を止める。

### 到達不能と未収録の一覧

静的リンク busybox の検証で確定した到達不能と未収録を置く。現段階の対象外であり、番号表の事実のみ持つか、検証の期待値として扱う。将来の VFS mounts合成＋`host`委譲可否判断時（別ADR）に再検討する。

| 区分 | 対象 | 振る舞い | 理由 |
|---|---|---|---|
| 到達不能 | `df` の `statfs`（x86_64 は 137、i386 は 99）と `fstatfs`（x86_64 は 138、i386 は 100）、i386 の `statfs64`（268）と `fstatfs64`（269） | 番号表のみ持ち、実行は未対応。`df` は `BIN-DISTRO 1.35.0` の x86_64 `137/statfs` で `mov $0x89,%eax; syscall`（`0x4ee6e9`）で止まる | 可搬な標準手段がなく、`cfg(target_*)` と `std::os::` は `host` と `jit` 以外で禁止、外部依存の追加は禁止、`forbid(unsafe_code)` のため生呼び出し不可、ホスト `df` 出力の転用は忠実度のため却下。CPU由来の合成（`/proc`等）は許容するが、ホストFS量の固定値は不可 |
| 未収録 | `join` | `busybox --list` に不在。`busybox join` は終了符号 127 で `join: applet not found` を出す。実機の静的リンク busybox と一致するため正規の振る舞いとして扱う | 実装対象のアプレットが存在しない。終了符号 127 を期待値とする |
| 番号の訂正履歴 | i386 の `GETGROUPS`（80）と `GETGROUPS32`（205） | 旧表は `GETGROUPS=99` と誤り、`STATFS=99` と衝突していた。`GETGROUPS=80` に訂正し、`STATFS=99`、`FSTATFS=100`、`GETGROUPS32=205` を番号表に持つ。x86-64 経路への影響はない | 値は Linux の UAPI ヘッダ由来の事実であり、`heavy_abi_uapi` の i386 の突き合わせで固定する |

## Linux のシステムコールの実装の段階

Linux のシステムコールは、動かせるプログラムの範囲が広がる順に実装する。

| 段階 | 動くもの | 主なシステムコール |
|---|---|---|
| 1 | 静的リンクの「hello world」 | `write`、`exit_group`、`brk`、`mmap`、`munmap`、`uname`、TLS の設定（`set_tid_address`、`arch_prctl`、`set_thread_area` など）、`getrandom`、`clock_gettime` |
| 2 | 動的リンクのプログラム、ファイル操作 | `openat`、`read`、`pread64`、`lseek`、`close`、`fstat`、`newfstatat`、`statx`、`getdents64`、`mprotect`、`fcntl`、`dup3`、`ioctl`（端末の問い合わせ）、`readlinkat`、`getcwd` |
| 3 | 複数スレッドのプログラム | `clone`（スレッド）、`futex`、`set_robust_list`、`rt_sigaction`、`rt_sigprocmask`、`rt_sigreturn`、`tgkill`、`sigaltstack` |
| 4 | シェルとコマンド群（busybox など） | `clone`（プロセス）、`execve`、`wait4`、`pipe2`、`kill`、`setpgid`、`chdir` |
| 5 | ネットワークと待ち合わせ | ソケット関連、`poll`、`ppoll`、`epoll_*`、`timerfd_*`、`eventfd2` |

## WASI

`os-wasi` は WASI preview1 の関数を、仮想カーネルの機構を使って実装する。ファイル記述子の表と仮想ファイルシステムは Linux パーソナリティと共有し、プリオープンのディレクトリは仮想ファイルシステムのディレクトリに対応させる。WebAssembly にはシグナルと `fork` がないので、これらの機構は使わない。

WebAssembly のモジュールでは、WASI の関数はシステムコール命令ではなくインポートした関数の呼び出しとして現れる。WebAssembly のゲスト ISA は、ホスト関数のインポートの呼び出しを `Stop::Syscall` と同じ種類の退出として返し、`os-wasi` がそれを処理する。
