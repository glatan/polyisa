# 観測とデバッグ

この文書は、polyisa の実行を観測し、ゲストのプログラムと polyisa 自身をデバッグするための機能を定める。対象は `trace` クレート、`gdbstub` クレート、`diag` クレート、`cli` のサブコマンドである。エンジン側の観測点の仕組みは [実行エンジン](execution-engine.md) にある。

## コマンドラインの構成

`polyisa` コマンドは次のサブコマンドを持つ。

| サブコマンド | 機能 |
|---|---|
| `run` | ゲストのプログラムを実行する。CPU モデル、OS パーソナリティ、ゲストのルート、タイミング、トレース、GDB の接続を指定する |
| `cpus` | ISA ファミリ、CPU モデル、グループ、機能、挙動パラメータの一覧を表示する |
| `disasm` | ファイルやバイト列を、指定した CPU モデルで逆アセンブルする |
| `asm` | ISADL から生成したエンコーダで命令列を組み立てる。主にテストの作成に使う |

## 命令トレース

命令トレースは、実行したステップを 1 行ずつ記録する。各行は、通し番号、仮想時間、ゲストスレッド、プログラムカウンタ、命令のバイト列、逆アセンブルの結果、書き換えたレジスタの新しい値、メモリアクセスのアドレスと値を持つ。記録する範囲は、アドレスの範囲、通し番号の範囲、ゲストスレッドで絞り込める。

トレースの書式は行単位のテキストとし、書式を文書化して固定する。書式を固定するのは、他のエミュレータのトレースとの比較と、polyisa の版の間の比較に使うからである。他のエミュレータの出力は書式が異なるので、devtool（[開発作業とローカル検証](dev-workflow.md)）に、他のエミュレータのトレースを polyisa の書式に変換する処理を置き、変換後の二つのトレースを比較して、最初に食い違ったステップを報告する。

## システムコールトレース

システムコールトレースは、ゲストスレッドごとに、システムコールの名前、引数、戻り値を記録する。引数は ABI 表を使って、フラグを名前に、構造体を中身に展開して表示する。戻り値がエラーなら `errno` の名前を表示する。表示は strace の形式に近づけ、Linux 上の strace の出力と読み比べられるようにする。

## ブロックの記録

ブロックの構築、無効化、JIT による変換、連結を記録する。自己書き換えコードの扱いの誤りや、デコードキャッシュの古い内容の実行を調べるときに使う。

## 統計

実行の終了時に、次の統計を表示できる。

- 実行したステップ数、仮想時間、ステップあたりのサイクル数
- 命令の分類ごとの実行回数
- タイミングモデルが有効な場合、キャッシュの段ごとのヒットとミス、分岐予測の失敗の回数
- ゲストのプログラムのシンボル表がある場合、関数ごとのステップ数とサイクル数

## 逆アセンブラ

逆アセンブラは ISADL から生成する（[ISA 記述言語](isa-description.md)）。逆アセンブルの結果は、命令トレース、未実装の命令の報告、GDB の接続とは別の利用者向けの表示で使う。逆アセンブラはデコーダと同じ記述から作られるので、デコーダの誤りは逆アセンブルの誤りとしても現れる。これを利用して、外部の逆アセンブラとの比較でデコーダを検証する（[検証戦略](testing.md)）。

## GDB の接続

`polyisa run -g <ポート>` は、GDB リモートシリアルプロトコルのサーバを開き、GDB の接続を待ってからゲストのプログラムを始める。サーバは `std::net` の TCP で動く。対応する操作は次のとおりである。

- レジスタとメモリの読み書き。レジスタの一覧は、ゲスト ISA のレジスタ記述から、GDB の標準の機能名（`org.gnu.gdb.riscv.cpu` など）を使ったターゲット記述として生成する。
- ブレークポイント。ゲストのメモリを書き換えず、エンジンのブレークポイントの表に登録する（[実行エンジン](execution-engine.md)）。
- シングルステップ。インタプリタで 1 ステップずつ実行する。
- ウォッチポイント。メモリアクセスの観測点で実現する。
- 複数のゲストスレッドの一覧と切り替え。
- ゲストのシグナルによる停止の報告。

## 未実装と異常の報告

未実装の命令、システムコール、機能に達したときの報告には、ゲストのプログラムカウンタ、命令のバイト列、逆アセンブルの結果（デコードできた場合）、CPU モデル、未実装の対象の名前を含める（[ワークスペース構成](workspace.md) のエラーの扱い）。

polyisa 自身がパニックしたときに原因を調べられるよう、直近に実行したブロックの入口のアドレスを vCPU ごとに環状のバッファへ記録する。ブロックの入口ごとの記録はステップごとの記録より費用が小さいので、常に有効にしておく。パニックの処理は、このバッファの内容を表示する。

## 内部の診断ログ

polyisa 自身の診断ログは、基礎層の `diag` クレートの小さなログ機構で出力する。`trace` に置かないのは、`trace` がツール層にあり、エンジンや仮想カーネルから使えないからである。環境変数 `POLYISA_LOG` で、出力する対象のクレートと水準を指定する。ログ機構は標準エラー出力に書くだけの単純なものにし、外部のログ用のクレートと同等の機能は求めない。
