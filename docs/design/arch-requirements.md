# アーキテクチャ固有の要求

この文書は、対象の ISA ファミリごとに、共通の設計に影響する性質を挙げ、それをどの仕組みで扱うかを対応づける。目的は、共通の抽象（ステップ、実行モード、動的なレジスタ参照、アクセス属性、OS パーソナリティなど）が、すべての対象 ISA の要求を受け止められることを、実装の前に確かめることである。

ISA ファミリごとの実装の詳細な設計は、その ISA ファミリの実装を始めるときに、ゲスト ISA クレートの文書として別に書く。この文書は、共通の設計への要求だけを扱う。

## 複数の ISA にまたがる仕組み

### OS による命令の補完

いくつかの ISA では、CPU が実装しない命令や、CPU が例外を起こす状況を、OS のカーネルがソフトウェアで補完し、ユーザーのプログラムからは命令が実行されたように見える。68040 と 68060 の浮動小数点と整数の未実装命令（Linux は Motorola のエミュレーションのパッケージを持つ）、MicroVAX が省いた十進命令と文字列命令、Alpha の非整列アクセスと IEEE の例外の補完、FPU を持たない MIPS の浮動小数点命令と `RDHWR`、Power の `MFPVR`、ARM の VFP の例外処理がこれにあたる。

polyisa では、CPU モデルはその CPU が実装する命令だけを持ち、補完される命令は未定義命令などの例外を起こす。OS パーソナリティは、ゲスト ABI ごとの補完の表に従い、その例外を受けて命令を実行し、CPU モデルに設定した補完のサイクル数を仮想時間に足す。命令の実行には、ゲスト ISA の意味論を、補完の対象の命令を含む機能集合で使う。この分担により、CPU モデルの機能集合は実機の CPU と一致したまま、OS のもとでのプログラムの振る舞いも再現できる。

### 特別なアドレスを経由する OS の呼び出し

システムコール命令ではなく、特定のアドレスへの分岐で OS の機能を呼ぶ ABI がある。PA-RISC の Linux はゲートウェイページへの `ble 0x100(%sr2, %r0)` でシステムコールを行う。ARM の Linux は高位アドレスに kuser helper（`__kuser_cmpxchg`、`__kuser_get_tls` など）を置き、x86-64 の Linux は旧来の vsyscall ページを持ち、IA-64 の Linux はゲートページに高速なシステムコールを置く。

OS パーソナリティは、これらのアドレスのページを、命令フェッチで退出を起こす特別なページとしてアドレス空間に写像する。エンジンは、そのページからブロックを構築しようとした時点で退出を返し、OS パーソナリティがアドレスに対応する処理を行う。

### 再開可能な不可分列

SuperH の Linux は、ユーザー空間の命令列を不可分に実行するために gUSA を使う。決まったレジスタの値で示された命令列の途中でスレッドが切り替わると、カーネルが命令列の先頭に戻す。Linux の rseq も、ISA によらず同じ種類の規約である。

polyisa のスケジューラはステップの境界でゲストスレッドを切り替えるので、この規約を守るには、切り替えのときに OS パーソナリティが命令列の途中かどうかを調べ、途中なら先頭に戻す必要がある。OS パーソナリティは、スレッドの切り替えの直前に呼ばれる関数を、ゲスト ABI ごとに持てるようにする。

### トランザクショナルメモリ

x86 の TSX、Power の HTM、s390 のトランザクション実行は、CPU の世代によって有無が異なり、実機でもトランザクションの失敗を許す。polyisa は当面、トランザクションの開始を常に失敗させる。この振る舞いは仕様が許す範囲にあり、正しいプログラムは失敗時の代替の経路で動作を続ける。トランザクションの成功を再現する必要が生じたら、挙動パラメータで切り替えられるようにする。

## ISA ファミリごとの要点

### x86

版の範囲は 8086 から x86-64 までで、ベンダーの差（Intel、AMD など）と、x87、MMX、3DNow!、SSE 系、AVX 系、AVX-512 のサブセット、AVX10、ACE、AMX、APX などの拡張を含む。拡張の全範囲は、Intel SDM と AMD APM の台帳で確認した版が定めるユーザーモード命令に従う。x86-64 のマイクロアーキテクチャのレベル（v1 から v4）はプロファイルとして表す。

- 1 から 15 バイトの可変長命令と接頭辞（REX、VEX、EVEX、REX2）は、ISADL のオペコード表と ModRM のフックで扱う。
- 既定のオペランドサイズとアドレスサイズ、64 ビットモードは実行モードとする。ユーザーモードで必要なのは 32 ビットのプロテクトモードと 64 ビットモードである。
- ユーザーモードでも、FS と GS のベース（TLS）と、32ビット Linux（i386 ABI）の `set_thread_area` による GDT の項目が必要なので、セグメントの最小限のモデルを CPU 状態に持つ。
- 未定義のフラグの値と、BSF などの境界条件の振る舞いは、Intel と AMD で異なるので挙動パラメータとする。
- 8086 と 8088 の命令プリフェッチキューは、直後の命令の書き換えの結果を変える。これは機能の側で、該当する CPU モデルのステップの構成として扱う（[タイミングモデル](timing.md)）。
- 8086 と 80286 の世代は Linux で動かないので、裸実行環境で命令を検証する。

### ARM（AArch32 とそれ以前）

版の範囲は ARMv2 から Armv8-A の AArch32 までで、Thumb、Thumb-2、VFP、NEON を含む。

- ARM と Thumb の切り替えは実行モードとする。Thumb-2 の IT ブロックの状態は、ブロックの開始時の値を実行モードに含め、ブロック内ではデコーダが命令ごとに追跡する。
- ほぼ全命令の条件実行は、意味論の `if_then` で書く。
- ARMv6 より前の非整列 `LDR` の回転は、挙動パラメータと意味論で扱う。
- ビッグエンディアンの方式（ARMv6 より前の BE32 と、ARMv6 以降の BE8）は、命令フェッチとデータアクセスのエンディアンの組み合わせとして、実行モードとアクセス属性に反映する。
- ARMv2 と ARMv3 の 26 ビットアドレスのモードは、Linux のユーザーモードでは使われないので、裸実行環境での検証に限る。
- M プロファイルは MMU を持たず Linux が動かないので、裸実行環境と将来のセミホスティングのパーソナリティで扱う。

### AArch64

版の範囲は Armv8.0-A から Armv9.x-A までで、数百の `FEAT_*` を機能として表す。

- 固定長 32 ビットで、ISADL のビットパターンで素直に記述できる。
- SVE のベクトル長は CPU モデルのパラメータだが、Linux では `prctl` でプロセスごとに変えられ、SME のストリーミングモードでも変わる。ベクトル長とストリーミングモードは実行モードに含める。
- ユーザー空間からの ID レジスタの読み出しは、Linux がエミュレーションしている。OS パーソナリティが、CPU モデルの識別情報から値を返す。
- MTE（メモリタギング）は、16 バイトごとのタグをメモリに持つ必要があり、`mem` に追加の記憶域を要する。MTE は後の段階で扱い、それまでは機能として提供しない。

### MIPS

版の範囲は MIPS I から MIPS V、MIPS32 と MIPS64 の Release 1 から Release 6 までで、microMIPS、MIPS16e、DSP、MSA、ベンダーの拡張（R5900 の 128 ビットのレジスタと MMI など）を含む。

- 遅延スロットと branch likely は、ステップの構成で扱う。Release 6 の遅延スロットのない分岐は、ふつうの 1 命令のステップになる。
- MIPS I のロードの遅延スロット（ロードの直後の命令はロード前の値を読む）は、R2000 と R3000 の CPU モデルで、機能の側で再現する。
- Release 6 によるオペコードの割り当て直しは、機能を条件とする別の命令として宣言する（[ISADL](isa-description.md)）。
- MIPS16e と microMIPS の ISA モード（分岐先アドレスの最下位ビット）と、FPU の FR モードは実行モードとする。
- NaN の符号化（旧来と IEEE 754-2008）は、ELF のフラグで決まるプロセスの属性として、プロセスの開始時に設定する。
- o32、n32、n64 はゲスト ABI の変種であり、システムコール番号の基点が異なる。

### RISC-V

版の範囲は RV32I、RV64I、RV32E と、各拡張、プロファイル（RVA20、RVA22、RVA23 など）、ベンダーの拡張である。

- 圧縮命令による 16 ビットと 32 ビットの混在は、デコーダの入口の長さの規則で扱う。
- RV32 の実行時は、GPR に下位 32 ビットの符号拡張値を置き、演算は W 接尾辞と同じ 32 ビット演算で行い、分岐・ジャンプの飛び先とロードストアのアドレスは 32 ビットで包む。XLEN の違いによる意味論の切り替えは、CPU モデルが実行中に変わらないのでデコード時に関数選択で済ませる。
- ベクトル拡張の 0.7.1（T-Head の実装）と 1.0 はエンコーディングが衝突するので、`conflicts` を宣言した別の機能にする。
- ベクトル拡張の `vtype` は実行中に変わる。インタプリタでは実行時の値として読み、JIT では `vtype` を実行モードに含めて特殊化することを、JIT の段階で検討する。
- 非整列アクセスを許すかどうかは実装によって異なるので、挙動パラメータとする。

### Power

版の範囲は POWER、PowerPC（601 から 970 まで）、Power ISA 2.0x から 3.1 まで、組み込み向けの Book E（e500 の SPE を含む）である。

- POWER の命令と MQ レジスタを持つ 601 は、POWER の機能と PowerPC の機能の両方を持つ CPU モデルとして表す。
- e500 の SPE は AltiVec とエンコーディングが衝突するので、`conflicts` を宣言する。
- ISA 3.1 の 8 バイトの接頭辞付き命令は、デコーダの入口の長さの規則で扱う。
- リトルエンディアンのモード（Linux の `switch_endian` で切り替えられる）は実行モードとする。
- `MFPVR` は特権命令だが、Linux がユーザー空間向けに補完する（OS による命令の補完）。

### s390 系

版の範囲は System/360 から z/Architecture までで、z/Architecture の世代ごとのファシリティを機能として表す。

- 命令長は先頭 2 ビットで決まる 2、4、6 バイトである。
- 24、31、64 ビットのアドレッシングモードは実行モードとする。
- `EX` と `EXRL` は、別の命令の 2 バイト目をレジスタの値で変更してから実行する。対象の命令は実行時に決まるので、ステップの中で対象の命令をデコードし、変更後の命令語をキーとする小さなデコードキャッシュを使う。
- `MVCL` などの中断可能な命令は、反復のステップで扱う。
- 16 進浮動小数点、二進浮動小数点、十進浮動小数点、パック十進命令を持つ。
- Linux が動く世代は ESA/390 の後期と z/Architecture に限られるので、それより前の世代は裸実行環境で検証する。

### WebAssembly

版の範囲は 1.0、2.0、3.0 と、各提案である。

- WebAssembly は、モジュールの検証を経てから実行する。ゲスト ISA クレートが、モジュールの読み込みと検証を行い、関数ごとに実行用の内部形式を作る。
- プログラムカウンタは関数の番号と関数内のオフセットの組であり、これをブロックキーの値に符号化する。コードは線形メモリの外にあるので、自己書き換えコードは起こらない。ブロックキーのページフレームには、コード用の仮想的なページフレームの識別子を割り当てる。
- オペランドスタックとローカル変数は、検証の段階で位置が静的に決まるので、フレームの基底からの位置で参照する動的なレジスタ参照として扱う。
- 線形メモリは、一つの写像だけを持つアドレス空間として表す。範囲外のアクセスはページフォールトではなくトラップとして退出する。
- WASI の関数はインポートの呼び出しとして現れ、OS パーソナリティが処理する（[ユーザーモード](user-mode.md)）。
- GC の提案は、線形メモリとは別のゴミ集め付きのヒープを必要とする。ゲスト ISA クレートの中の別の構成要素として、後の段階で扱う。
- 浮動小数点の NaN は正準 NaN に固定し、relaxed SIMD の実装定義の結果は挙動パラメータで決定的な値を選ぶ。

### m68k

版の範囲は 68000 から 68060 まで、CPU32、ColdFire、68881 と 68882 の FPU である。

- 2 から 22 バイトの可変長命令は、実効アドレスと拡張語のフックで扱う。
- 68000 と 68010 は奇数アドレスへのワードとロングワードのアクセスでアドレスエラーを起こし、68020 以降は起こさない。CPU モデルごとにアクセス属性のアライメントを切り替える。
- 68040 と 68060 の未実装命令は、OS による命令の補完で扱う。
- BCD 命令の未定義のフラグの値は、世代ごとに挙動パラメータとする。

### VAX

版の範囲は VAX-11/780 から NVAX まで、MicroVAX のサブセット、F、D、G、H の浮動小数点形式である。

- 命令はオペコードと、16 種のアドレッシングモードを持つオペランド指定子の列からなり、オペランド指定子のフックでデコードする。オペランド指定子の自動増減の副作用の順序は、仕様書の規定に従って意味論で書く。
- `CALLS` と `RET` は、呼び出し先の入口のレジスタ保存マスクに従ってフレームを作り、戻す。
- `MOVC3` などの中断可能な命令は、反復のステップと、仕様書が規定する途中状態で扱う。
- MicroVAX が省いた命令は、OS による命令の補完で扱う。
- 主流の Linux の移植がないので、BSD のパーソナリティを将来の対象とし、それまでは裸実行環境で検証する。

### PDP-11

版の範囲は 11/03 から J-11 までの各モデルと、EIS、FIS、FP11、CIS の各オプションである。

- 各モデルの間の振る舞いの差（`MOV R0,(R0)+` の結果など）は、プロセッサハンドブックの差の一覧に基づく挙動パラメータとする。
- 32 ビットの値は、16 ビットのワードを上位から並べる配置でメモリに置く。意味論が 16 ビットのアクセスの組で書く。
- 11/45 や 11/70 の命令空間とデータ空間の分離（Unix V7 の分離 I&D の実行ファイル）は、命令フェッチとデータアクセスで別のアドレス空間を選ぶことを要する。実装は `mem` に空間選択を拡張せず、ゲスト側がモード×I/D の PAR/PDR 集合で仮想アドレスを物理アドレスへ変換し、物理メモリは単一のアドレス空間とする形とした（設計との差の台帳 GAP-0085）。`mem` には、アクセスの種類ごとにアドレス空間を選べる拡張の余地を残してある。
- Unix V7 のパーソナリティを将来の対象とする。

### SPARC

版の範囲は V7、V8、V9 と VIS である。

- レジスタウィンドウは動的なレジスタ参照で扱う。ウィンドウ数は CPU モデルのパラメータである。ウィンドウのあふれと不足のトラップは、Linux のカーネルが行うスタックへの退避と復元を、OS パーソナリティが再現する。
- 遅延スロットと annul ビット、遅延スロット内の分岐（DCTI couple）の規定どおりの振る舞いは、ステップの構成で扱う。
- V9 のユーザーが使える ASI（リトルエンディアンのアクセスなど）は、即値の ASI ならデコード時に、`%asi` レジスタの値なら実行時に、アクセス属性へ反映する。
- 32 ビットのプログラムのためのアドレスマスク（PSTATE.AM）は実行モードとする。

### Alpha

版の範囲は 21064 から 21364 までと、BWX、FIX、CIX、MVI の各拡張である。`AMASK` と `IMPLVER` が返す値は識別情報として扱う。

- システムコールと TLS は `CALL_PAL` で行う。PAL コードの役割は OS パーソナリティが果たす。
- 浮動小数点の不正確な例外とソフトウェアによる補完、非整列アクセスの補完は、OS による命令の補完で扱う。polyisa の浮動小数点の例外は常に正確に起こる。
- ページサイズは 8 KiB である。

### PA-RISC

版の範囲は PA-RISC 1.0、1.1、2.0 と MAX である。

- 命令アドレスキュー（前と後の二つのプログラムカウンタ）と遅延分岐は、ステップの構成で扱う。
- 無効化（nullification）は、PSW の N ビットを CPU 状態に持ち、ステップの先頭で調べる（[命令意味論](semantics.md)）。
- Linux のシステムコールは、ゲートウェイページへの分岐で行う（特別なアドレスを経由する OS の呼び出し）。
- NaN の符号化は MIPS の旧来の方式と同じ向きである。

### SuperH

版の範囲は SH-1 から SH-4A まで（SH-5 は別の ISA なので含めない）と、SH-2 互換の J-core である。

- SH-2A の 32 ビット命令は、デコーダの入口の長さの規則で扱う。
- SH-4 の FPSCR の PR、SZ、FR は浮動小数点命令の意味を変えるので実行モードとし、FPSCR に書く命令でブロックを終える。
- 遅延スロットの中の分岐は、スロット不正命令の例外とする。
- Linux の gUSA は、再開可能な不可分列で扱う。

### LoongArch

版の範囲は LA32 と LA64、LSX、LASX、LBT の各拡張である。

- 固定長 32 ビットで、ISADL のビットパターンで記述できる。
- LBT は、x86 と ARM のフラグと x87 のスタックの状態を CPU 状態に持つ拡張であり、CPU 状態の構造体に含める。
- `CPUCFG` 命令が返す値は識別情報として扱う。
- 初期の独自の ABI と、Linux の本流の ABI は、ゲスト ABI の変種として区別できるようにする。

### OpenRISC

版の範囲は OpenRISC 1000 アーキテクチャの各版と、浮動小数点の拡張である。

- アーキテクチャ仕様 1.1 以降は、遅延スロットを持たない実装を許す（CPUCFGR の ND ビット）。遅延スロットの有無を機能とし、分岐のステップの構成を切り替える。

### IA-64

版の範囲は Itanium から Itanium 9700 系までである。IA-32 の実行層は対象にしない。

- 128 ビットのバンドル（テンプレートと 3 つのスロット）は、テンプレートからスロットの種類を決め、種類ごとのデコーダの入口でデコードする。ステップはバンドルとする。
- 述語レジスタによる条件実行は、命令ごとに `if_then` で書く。
- 回転レジスタとレジスタスタックは、動的なレジスタ参照で扱う。レジスタスタックの退避先（バッキングストア）の内容はユーザーのプログラムから読めるので、`flushrs` の実行時と、物理レジスタの数（CPU モデルのパラメータ）を超えたときに、ゲストのメモリへ実際に書き出す。
- 制御投機の NaT ビットと、データ投機の ALAT は CPU 状態に持つ。ALAT の容量と置換の方針は挙動パラメータとし、ストアのたびに ALAT の該当する項目を無効にする。ALAT が空のときは、この検査を省く。
- 例外の報告には、バンドルのアドレスとスロットの番号を含める。
- Linux のシステムコールは `break 0x100000` と、ゲートページの高速なシステムコールで行う。

### Hexagon

版の範囲は V5 以降の各版と、HVX である。

- パケットはステップとし、パケットの終わりで書き込みをまとめて反映する（[命令意味論](semantics.md)）。`.new` オペランドと `.new` 述語は、同じパケットの一時値を読む。
- デュプレックス（32 ビットに 2 つの 16 ビットの命令を詰めた形式）は、専用のデコーダの入口でデコードする。
- 定数拡張子（`immext`）は、次の命令の即値の上位ビットを与える。パケットのデコードの中で、次の命令のオペランドに合成する。
- ハードウェアループの終端は、パケット内の解析ビットで示される。ステップの最後に、ループのカウンタと開始アドレスに従って次のプログラムカウンタを決める。
- 実機は複数のハードウェアスレッドを交互に実行する構造なので、タイミングモデルは専用のものを用意する。
