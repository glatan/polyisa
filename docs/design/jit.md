# IR と JIT

この文書は、後の段階で追加する IR（`ir` クレート）と JIT（`jit` クレート）の設計の骨格を定める。実装は、インタプリタで少なくとも三つの ISA が正しく動いた後に始める（[ロードマップ](roadmap.md)）。それより前にこの文書を置くのは、インタプリタの段階の設計（バックエンドトレイト、ブロック、退出、タイミングとの接続）が JIT の追加を妨げないことを確認するためである。

## JIT が守る制約

JIT の追加は、次の二つを変更しない。

1. ゲスト ISA の命令意味論。JIT は、意味論を IR のバックエンドで実行して IR を得る（[命令意味論](semantics.md)）。
2. 実行結果。同じ入力に対して、JIT による実行とインタプリタによる実行は、ブロックの境界ごとに同じ CPU 状態とメモリの内容を与える。タイミングの忠実度が同じなら、仮想時間も一致する。

2 により、インタプリタは JIT のテストのオラクルになる（[検証戦略](testing.md)）。

## 階層化

エンジンは、まずインタプリタでブロックを実行し、ブロックごとの実行回数を数える。回数が閾値を超えたブロックを IR に変換し、最適化し、機械語に変換する。機械語のブロックは、インタプリタのブロックと同じブロックキーで登録し、同じ無効化の仕組みで破棄する。

## IR

IR はブロック単位の SSA 形式である。値は幅（1、8、16、32、64、128 ビット）を持ち、操作はバックエンドトレイトの操作と一対一に対応する。

- CPU 状態の読み書きは、`StateRef` のオフセットと幅を持つ操作になる。動的なレジスタ参照は、配列の基底と添字を持つ操作になる。
- メモリアクセスはアクセス属性を持つ。
- ヘルパーの呼び出しは、ヘルパーが宣言した副作用（読み書きする CPU 状態の範囲、メモリアクセス、例外の可能性）を持つ。
- ブロック内の制御は、`if_then` と `if_then_else` から作られる非循環の分岐と合流だけである。ステップの中でループを書かない規則（[命令意味論](semantics.md)）により、ブロック内にループは現れない。
- ブロックの出口は、飛び先が定数の直接の出口、飛び先が実行時の値の間接の出口、例外の出口、システムコールの出口に分かれる。

例外の出口は、例外を起こしうる操作ごとに、そのステップのゲストのアドレスと例外の情報を定数として持つ。ホストの機械語のアドレスからゲストのアドレスを逆引きする表を持たないかわりに、出口ごとに小さなコード片が増える。逆引きの表を持たないのは、表の構築と検索の実装が、ホストのバックエンドごとに必要になるからである。

## 最適化

最適化は、ブロック内で完結するものから始める。

- 定数の畳み込みと、コピーの伝播
- 共通部分式の削除
- CPU 状態のフィールドへの、読まれずに上書きされる書き込みの削除。遅延評価の条件フラグの保存や、使われないフラグの計算がこれで消える
- ゲストのレジスタをホストのレジスタに保持し、CPU 状態との読み書きをブロックの入口と出口と、ヘルパーの呼び出しの前後に限る

ブロックをまたぐ最適化（スーパーブロックやトレースの形成）は、ブロック内の最適化の効果を計測した後に検討する。

IR の解釈実行器も用意する。これは性能のためではなく、ホストのバックエンドがない環境でも、IR のバックエンドと最適化をテストするためである。

## ホストのバックエンド

ホストのバックエンドは、命令選択とブロック内の線形走査によるレジスタ割り付けを行い、ホストの機械語を出力する。最初のバックエンドは x86-64（System V の呼び出し規約）とし、次に AArch64 を検討する。命令のエンコードには、x86 と AArch64 の ISADL の記述から生成したエンコーダを使う（[ISA 記述言語](isa-description.md)）。`jit` はゲスト ISA クレートに依存せず、`jit` の `build.rs` が `isagen` を使って、該当する ISADL の記述からエンコーダだけを生成する。

ホストのバックエンドがないホストでは、JIT を無効にしてインタプリタだけで実行する。JIT の有無は実行結果を変えないので、ホストへの移植の最初の段階では JIT を省ける。

### 実行可能メモリ

生成した機械語を置くメモリは `host` クレートから得る（[ホスト抽象化](host.md)）。書き込み可能かつ実行可能なページは作らず、書き込み可能な状態で機械語を書いてから、実行可能に切り替える。AArch64 のホストでは、切り替えの後に命令キャッシュを同期する。

### 機械語の中のメモリアクセス

機械語は、ソフトウェア TLB の検索を命令列として埋め込む。タグが一致すれば、ページフレームのホストアドレスにオフセットを足してアクセスし、一致しなければ低速経路の関数を呼ぶ。低速経路は、ページフォールトのときに状態の値を返し、機械語はその値を検査して例外の出口に進む。

### ブロックの連結

直接の出口の飛び先が変換済みのブロックであれば、出口の分岐命令を飛び先のブロックへ書き換えて連結する。飛び先のブロックが無効化されたら、連結を外す。間接の出口は、ジャンプキャッシュを引く共通のコード片へ進む。

## タイミングとの接続

JIT がタイミングモデルを扱う方法は、CPU モデルのタイミングの忠実度によって変わる（忠実度の定義は [タイミングモデル](timing.md)）。

- `none` と `cpi`：ブロックのサイクル数は、ステップごとのサイクル数の和として変換時に求まるので、ブロックの出口で仮想時間に定数を足す。
- `exact` と `approx`：機械語が、ステップごとの命令イベントをバッファに書き込む。タイミングモデルは、バッファが満ちたときと、ゲストが時刻を読むときにまとめて消費する。命令イベントの静的な部分はデコード済みステップへの参照で済むので、機械語が書くのは動的な部分（アクセスしたアドレス、分岐の結果、タイミングの手がかり）だけである。

`exact` と `approx` では、命令イベントの記録の費用が JIT による高速化の大部分を打ち消す可能性がある。その場合でも、命令の解釈の費用がなくなる分は速くなると見込んでいるが、効果は実装後に計測して判断する。

## 観測点との関係

JIT が対応する観測は、ブロック単位のトレースと統計に限る。ステップ単位のトレース、メモリアクセスの監視、シングルステップ実行を要求された場合、エンジンは該当するブロックをインタプリタで実行する。
