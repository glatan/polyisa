# ゲストメモリ

この文書は、ゲストのメモリを表現する `mem` クレートの設計を定める。ゲストのアドレス空間をホストのアドレス空間に直接写さず、ソフトウェアのページ表で表現する理由は [ADR-0008](../adr/0008-software-page-table.md) にある。

## 前提

ゲストのメモリは 8 ビットバイト単位でアドレス付けされる。ゲストのアドレスは `u64` で表し、32 ビットや 31 ビットの ISA でのアドレスの折り返しは、命令意味論がアドレス計算の段階で行う。`mem` はアドレスの幅を解釈しない。

ゲストのデータはホストのメモリにバイト列として置き、ホストのエンディアンで解釈しない。ゲストの多バイトの値の読み書きは、常にアクセス属性で指定したエンディアンで変換する。これにより、ホストがビッグエンディアンでも、`mem` とその利用者のコードは変わらない。

## アドレス空間

アドレス空間は、ゲストのページ番号からページ表の項目への写像である。ページ表は 4 KiB を単位とし、64 ビットのアドレス空間の一部だけが使われることを前提に、疎な多段の基数木で表す。IA-64 の Linux のように、ゲストのアドレス空間の上位ビットで領域を分ける ABI があり、使われるアドレスが 64 ビットの範囲に散らばるからである。

ページ表の項目は次のものを持つ。

- ページフレームへの参照、またはまだ割り当てていないことを示す状態（ゼロ埋めの匿名ページ、ファイルの内容を読み込む前のページ）
- 読み、書き、実行の許可
- コピーオンライトの印
- そのページフレームがデコード済みのコードを含むかどうか（ページフレーム側に持つ。後述）

`mem` が提供するのは、範囲の写像、写像の解除、許可の変更、アドレス空間の複製といったページ単位の操作である。`mmap` の引数の解釈、仮想メモリ領域の一覧、スタックの自動拡張、`/proc/self/maps` の内容は、仮想カーネルと OS パーソナリティが決める（[ユーザーモード](user-mode.md)）。

### ゲストのページサイズ

ゲストのページサイズはゲスト ABI の性質であり、Alpha と SPARC64 では 8 KiB、IA-64 と LoongArch の Linux では 16 KiB が一般的で、Power の Linux では 64 KiB のことが多い。`mem` は 4 KiB の単位で管理し、ゲストのページは単位の整数倍として扱う。ゲストのページサイズでの整列とページサイズの報告（`AT_PAGESZ`、`getpagesize`）は OS パーソナリティが行う。

ページサイズが 4 KiB 未満のゲスト ABI は対象に含めない。ユーザーモードの対象 ABI で、ページサイズが 4 KiB 未満のものは今のところ見つかっていない。必要になったら管理の単位を見直す。

## ページフレーム

ページフレームは、4 KiB のゲストのデータを保持するホストのメモリ片である。複数のアドレス空間から共有でき、参照の数を数える。ページフレームは大きな塊でホストから確保し、ページフレームごとのホストへの確保要求を避ける。

ページフレームは次の二つの印を持つ。

- コードを含む：このページフレームからデコードしたブロックが存在する。印の付いたページフレームへの書き込みは低速経路を通り、ブロックの無効化を起こす（[実行エンジン](execution-engine.md)）。
- 共有のファイル写像に属する：`MAP_SHARED` のファイル写像のページフレームであり、書き戻しの対象になる。

## ソフトウェア TLB

vCPU ごとに、ゲストのページからページフレームのホストアドレスへの変換を、直接写像のキャッシュとして持つ。項目は、読み、書き、命令フェッチのそれぞれについて、タグとホストアドレスを持つ。タグが一致しない場合と、書き込みの低速経路が必要な場合（コピーオンライトのページ、コードを含むページフレーム、未割り当てのページ）は、書き込み用のタグを無効にしておき、高速経路から外す。

高速経路は次の手順で終わる。

1. アドレスからキャッシュの添字を計算し、アクセスの種類に応じたタグと比較する。
2. アクセスがページ内に収まり、アクセス属性のアライメントの条件を満たすことを確認する。
3. ホストアドレスにページ内のオフセットを足し、指定したエンディアンでバイト列を変換する。

どれかの条件を満たさない場合は低速経路に進む。低速経路は、ページ表を引き、許可を確かめ、必要ならページフレームの割り当て、コピーオンライトの複製、ファイルの内容の読み込み、ブロックの無効化を行い、キャッシュの項目を更新する。許可がなければページフォールトの退出を返す。

アドレス空間の写像や許可が変わったときは、そのアドレス空間を使うすべての vCPU のキャッシュの、該当する項目を無効化する。

## アクセス属性

アクセス属性 `Access` は、意味論がメモリアクセスごとに指定する値であり、デコード時に決まる。

| 要素 | 値 |
|---|---|
| エンディアン | リトルエンディアン、ビッグエンディアン |
| アライメント | 自然な境界を要求する（違反は例外）、要求しない |
| 種類 | データの読み、データの書き、命令フェッチ、読み書き一体の不可分操作、予約付きロード、条件付きストア |

アライメントを要求しないアクセスがページ境界をまたぐ場合、低速経路は両方のページの許可を確かめてから、読み書きを行う。片方のページだけに書いた状態でページフォールトを返さないためである。

ARMv6 より前の非整列 `LDR` の回転や、MIPS の `LWL`/`LWR` のような ISA 固有の非整列アクセスの振る舞いは、アクセス属性では表さない。意味論が、整列したアクセスとビット操作を組み合わせて書く。

双エンディアンの ISA で、実行中にエンディアンが変わる場合（Power の Linux の `switch_endian` システムコール、ARM の `SETEND`）は、エンディアンを実行モードに含め、デコード時にアクセス属性へ反映する。

将来のシステムモードでは、アクセス属性に特権レベルとアドレス空間の識別子（SPARC の ASI など）を加える。ユーザーモードではこれらの要素を持たない。

## 不可分操作と予約

当面、ゲストスレッドは一つのホストスレッドの上で多重化し、ステップの途中では切り替えない（[ADR-0007](../adr/0007-deterministic-single-host-thread.md)）。この前提では、読み書き一体の不可分操作と比較交換は、通常の読みと書きの組で正しく実現できる。

予約付きロードと条件付きストア（MIPS の `LL`/`SC`、RISC-V の `LR`/`SC`、Power の `LWARX`/`STWCX.`、ARM の `LDREX`/`STREX`、Alpha の `LDx_L`/`STx_C`）は、vCPU ごとの予約として実現する。予約は、予約付きロードで設定し、条件付きストアの実行と、ゲストスレッドの切り替えで解除する。別のゲストスレッドは切り替えの後にしか実行されないので、切り替えで予約を解除すれば、他のスレッドによる書き込みを見逃すことはない。切り替えによる予約の喪失は、各 ISA が許している条件付きストアの失敗の範囲に収まる。

ゲストスレッドの命令はステップの境界でしか入れ替わらないので、ゲストから見えるメモリの順序は逐次一貫性を満たす。逐次一貫性は、Power や ARM のような弱いメモリモデルを持つ ISA にとっても許される振る舞いの一つであり、ゲストのプログラムの正しさを損なわない。ただし、弱いメモリモデルでしか起こらない並び替えは再現しない。

複数のホストスレッドでゲストスレッドを並列に実行する場合の設計（ホストの不可分命令への対応づけと、ゲストのメモリモデルを満たすためのフェンスの挿入）は、並列実行を導入するときに改めて決める。

## アドレス空間の複製

`fork` のためのアドレス空間の複製は、ページ表を複製し、書き込みが許可されたページを親子の両方でコピーオンライトの印付きにする。ページフレームは共有され、参照の数が増える。最初の書き込みで低速経路がページフレームを複製し、印を外す。

## ファイルの写像

非共有のファイル写像（`MAP_PRIVATE`）は、ページを「ファイルの内容を読み込む前」の状態で写像し、最初のアクセスで内容を読み込む。共有のファイル写像（`MAP_SHARED`）は、仮想カーネルが持つファイルごとのページフレームの表を通して、同じファイルを写像する複数のゲストプロセスでページフレームを共有する。共有のファイル写像の内容のホストのファイルへの書き戻しは、`msync`、`munmap`、プロセスの終了の時点で行う。ホストの別のプロセスが同じファイルを同時に書き換えた場合の一貫性は保証しない。

## メモリ量の上限

ゲストが確保できるページフレームの総量に、設定で上限を設ける。上限に達した場合、仮想カーネルは `mmap` や `brk` を `ENOMEM` で失敗させる。ホストのメモリを使い尽くしてホストの OOM killer に polyisa ごと停止されるより、ゲストのプログラムがエラーとして扱える形で失敗させるほうが、原因を特定しやすいからである。
