# 実行エンジン

この文書は、vCPU を実行する `engine` クレートの設計を定める。対象はインタプリタによる実行であり、JIT は [JIT](jit.md) で扱う。どちらの実行方式でも、ブロックの管理、退出、観測点、タイミングモデルとの接続はこの文書の設計を共有する。

## エンジンの入出力

エンジンは、vCPU を一つ受け取り、退出が起こるか実行予算を使い切るまで実行する。

```rust
pub enum Stop {
    Syscall,                    // システムコール命令を実行した
    Exception(GuestException),  // CPU 例外が起きた
    BudgetExhausted,            // 実行予算を使い切った
    Breakpoint(u64),            // デバッガのブレークポイントに達した
    Unimplemented(Unimpl),      // 未実装の命令や機能に達した
    Exit(u64),                  // ゲストが終了した（OS が解決済みの終了コード）
    Deadlock,                   // 実行できるスレッドがない
}

pub trait VcpuRunner {
    fn run(&mut self, ctx: &mut EngineCtx, budget: Budget) -> Stop;
}
```

`Stop` を受け取った呼び出し側（仮想カーネルか裸実行環境）が、システムコールの処理、シグナルへの変換、スケジューリングを行う。エンジンは OS の概念を持たない。

`VcpuRunner` はトレイトオブジェクトとして扱い、仮想カーネルはゲスト ISA の型を知らない。ゲスト ISA の型による単相化は `run` の内側で行う。`run` は 1 回の呼び出しで多数のステップを実行するので、トレイトオブジェクトの呼び出しの費用は無視できる。

実行予算はステップ数か仮想時間のサイクル数で与える。ホストの実時間では与えない。実時間で区切ると、スケジューリングの切り替え位置がホストの負荷で変わり、実行が決定的でなくなるからである。

## vCPU

vCPU は次のものを持つ。

- ゲスト ISA の CPU 状態（`#[repr(C)]` の構造体）
- 現在の実行モード
- ソフトウェア TLB（[ゲストメモリ](memory.md)）
- 属するアドレス空間への参照
- タイミングモデルの状態（有効な場合）
- 実行したステップ数などの計数

## ブロックとデコードキャッシュ

インタプリタは、ステップを実行のたびにデコードせず、ブロック単位でデコード結果をキャッシュする。

### ブロックキー

ブロックはブロックキーで識別する。ブロックキーは、命令を含むページフレームの識別子、ページ内のオフセット、実行モード、CPU モデルの世代（機能集合と挙動パラメータの値の版）の組である。CPU モデルの世代を含めるのは、CPU モデルによる意味論の切り替えをデコード時に解決する（[CPU モデル](cpu-models.md)）ため、モデルが違えば同じアドレスでもデコード結果を共有できないからである。実行時に `--cpu` の機能足し引きやパラメータ変更で世代が変わった場合は、該当するゲスト ISA のデコードキャッシュを破棄する。仮想アドレスではなくページフレームを使うのは、`fork` 後の親子のプロセスのように、同じページフレームを共有する複数のアドレス空間でデコード結果を共有でき、ページフレームへの書き込みで無効化すべきブロックを直接たどれるからである。

仮想アドレスからブロックを引くには、まずソフトウェア TLB で命令フェッチ用の変換を行う。この変換を毎回の分岐で行う費用を避けるため、vCPU ごとに、仮想アドレスと実行モードと CPU モデルの世代からブロックを引く直接写像のキャッシュ（ジャンプキャッシュ）を持つ。ジャンプキャッシュは、アドレス空間の写像が変わったとき（`munmap`、`mprotect`）、ブロックの無効化のとき、CPU モデルの世代が変わったときに消去する。

### ブロックの終端

ブロックの構築は、次のいずれかの条件でステップの追加を止める。

1. 制御を移すステップ（ISADL の属性 `branch`、`call`、`return`、`indirect`、`syscall`）を追加した。
2. 属性 `ends_block` を持つステップを追加した。実行モードを変えうる命令や、浮動小数点の制御レジスタへの書き込みがこれにあたる。
3. 次のステップがゲストのページ境界をまたぐか、次のページに入る。
4. ステップ数が上限（初期値 64）に達した。
5. 次のステップのアドレスにデバッガのブレークポイントがある。

3 を設けるのは、ブロックの無効化と命令フェッチの例外をページ単位で扱うためである。ページをまたぐ可変長命令は、その命令だけで一つのブロックを作り、両方のページフレームに登録する。

5 により、ブレークポイントの検査はブロックの構築時だけに行われ、ステップごとの検査は不要になる。ブレークポイントを追加・削除したときは、該当するページフレームのブロックを無効化する。

### デコード済みステップの表現

ブロックは、デコード済みステップの列を連続したメモリに持つ。各ステップは、ISADL から生成した単相化済みの意味論の関数へのポインタ、デコードしたオペランド、命令長、タイミング表の項目への添字を持つ。インタプリタは、ステップごとに命令の種類で分岐せず、関数ポインタを順に呼ぶ。CPU モデルによる意味論の切り替えは、デコード時に関数ポインタの選択として済んでいる（[CPU モデル](cpu-models.md)）。

## 実行ループ

実行ループは次の処理を繰り返す。

1. ジャンプキャッシュで、現在のプログラムカウンタと実行モードからブロックを引く。見つからなければ、ソフトウェア TLB とブロックの表を引き、それでもなければブロックを構築する。
2. ブロックのステップを順に実行する。各ステップの意味論は、次のプログラムカウンタを設定するか、退出を返す。
3. 退出なら、プログラムカウンタと CPU 状態を例外の規則（[命令意味論](semantics.md)）どおりに整えて `Stop` を返す。
4. 実行予算を確認し、使い切っていれば `Stop::BudgetExhausted` を返す。

実行予算の確認はブロックの終わりで行う。ブロックの長さには上限があるので、予算の超過は高々 1 ブロック分である。超過分は次の実行予算から差し引き、スケジューリングの位置を決定的に保つ。

ループの駆動と命令の実行は分かれる。`engine` は繰り返しと実行予算・退出の判定を担い、フェッチ・解読・意味論とトラップ境界の解決は、依存規則（[ワークスペース構成](workspace.md)）のため ISA ごとの `step` 実装が渡す（[ADR-0016](../adr/0016-execution-loop-driver.md)）。トラップの境界は `engine::run::TrapHandler` が定め、OS パーソナリティ（`os-linux`）が実装する。`engine::run::StepRunner` がこの駆動を `VcpuRunner` に適合する。

## 自己書き換えコード

デコード済みのブロックを含むページフレームには、コードを含む印を付ける。印の付いたページフレームへの書き込みは、ソフトウェア TLB の高速経路を通らず、低速経路でブロックの無効化を行う。無効化は、ページフレームに登録されたブロックをすべて破棄し、印を外す。

書き込みによって実行中のブロック自体が無効になった場合、エンジンは書き込みを行ったステップの完了後にブロックの実行を打ち切り、次のステップからデコードし直す。x86 は、直後の命令を書き換える自己書き換えコードについても、書き換え後の命令が実行されることを保証しているので、この処理が必要になる。

命令キャッシュの同期命令（ARM の `IC IVAU`、RISC-V の `FENCE.I`、Power の `ICBI`）を持つ ISA でも、同じ書き込み検出の仕組みを使う。同期命令の実行を待たずに無効化するので、実機より保守的に振る舞う。同期を怠ったプログラムが実機で古い命令を実行してしまう現象は再現しない。この差は実機で再現性の低い現象に限られるので、対象外とする。

## 観測点

エンジンは、トレース、デバッガ、統計のための観測点を、型引数 `O: Observer` として持つ。観測点は、ステップの実行前後、メモリアクセス、退出の各時点で呼ばれる。観測を行わない `NoObserver` では呼び出しがすべてインライン展開されて消えるので、観測を使わない実行に費用がかからない。

タイミングモデルへの接続も同じく型引数 `T: TimingSink` とする。タイミングが無効の場合は空の実装を使う。有効な場合、エンジンは各ステップの実行後に、そのステップに含まれる命令ごとに命令イベントを組み立てて渡す（パケットやバンドルのステップは複数の命令を含む）。命令イベントの静的な部分（命令の種類、オペランドの読み書き）はデコード済みステップから、動的な部分（アクセスしたアドレス、分岐の結果、意味論が渡したタイミングの手がかり）はインタプリタのバックエンドが実行中に記録する（[タイミングモデル](timing.md)）。

`O` と `T` の組み合わせごとに実行ループが単相化される。組み合わせは vCPU の作成時に一度だけ選ぶ。

## 裸実行環境

裸実行環境は、OS パーソナリティなしで vCPU とアドレス空間だけを作り、エンジンを実行するテスト用の環境である。テストは、メモリに命令列とデータを置き、レジスタを設定し、決まったステップ数か特定の退出まで実行して、CPU 状態とメモリを検査する。

ISA のバージョンのうち、Linux が動かない古い世代（8086、80286、S/360、POWER1 など）の命令の検証は、裸実行環境で行う。これらの世代でゲストのプログラムを動かすには、対応する OS パーソナリティが別に必要になる。

## 性能の目安

最初の目安は、タイミングモデルと観測を無効にした RISC-V の整数演算中心のプログラムで、ホストの 1 コアあたり毎秒 1 億ステップとする。この値は設計の比較のための仮の値であり、段階 1 で計測した結果を見て改める。性能の計測は `task bench` で行い、同じ入力の結果を記録して比較できるようにする（[開発作業とローカル検証](dev-workflow.md)）。
