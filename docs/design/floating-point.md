# 浮動小数点と十進演算

この文書は、ゲストの浮動小数点演算と十進演算を実装する `softfloat` クレートと `decimal` クレートの設計を定める。

## ホストの浮動小数点演算を使わない理由

ゲストの浮動小数点演算は、ホストの FPU ではなくソフトウェアで計算する。理由は三つある。

1. 丸めモードと例外フラグ：ゲストは丸めモードを命令ごとや制御レジスタで切り替え、例外フラグを読む。Rust の `f32` と `f64` は最近接偶数丸めに固定されており、ホストの浮動小数点環境を操作する手段が標準ライブラリにない。
2. ISA ごとの規則：アンダーフローの判定時期（丸めの前か後か）、NaN の伝播、非正規化数のフラッシュの規則が ISA によって異なる。ホストの FPU はホストの ISA の規則でしか計算しない。
3. IEEE 754 以外の形式：x87 の 80 ビット拡張精度、IBM の 16 進浮動小数点、DEC の浮動小数点形式、十進浮動小数点は、一般的なホストの FPU では計算できない。

ソフトウェアによる計算は、ホストに依存せず同じ結果を返すので、決定性の原則（[設計概要](overview.md)）とも合う。

## 扱う形式

| 形式 | 使う ISA |
|---|---|
| IEEE 754 binary16、binary32、binary64、binary128 | 大半の ISA |
| bfloat16 | x86（AVX-512 BF16）、AArch64、Power |
| 低精度形式（E4M3、E5M2、E2M1 など） | x86（AVX10.3、ACE） |
| x87 拡張精度（80 ビット） | x86 の x87 |
| 68881 拡張精度（96 ビットの格納形式、値は 80 ビット） | 68k の FPU |
| IBM 16 進浮動小数点（32、64、128 ビット） | s390 系 |
| DEC の F、D、G、H 形式 | VAX、PDP-11（F、D）、Alpha（F、G） |
| IEEE 754 decimal32、decimal64、decimal128（DPD 符号化） | Power、s390 系（`decimal` クレート） |

8 ビット（E4M3、E5M2）と 4 ビット（E2M1）の浮動小数点形式は、AVX10.3 と ACE を実装する段階 13 で追加する。

## ISA ごとの規則の渡し方

`softfloat` の演算は、オペランドと、演算の規則を表す環境 `FpEnv` を受け取り、結果と例外フラグを返す。`softfloat` 自身は ISA の名前を持たず、ゲスト ISA が自分の規則を `FpEnv` として与える。

| 環境の要素 | ISA による違いの例 |
|---|---|
| 丸めモード | IEEE の 4 種に加え、RISC-V の RMM（最近接、同距離は 0 から遠い側）、Power の奇数への丸め |
| アンダーフローの判定時期 | x86 と RISC-V は丸めの後、ARM は丸めの前 |
| NaN の伝播規則 | x86 は第 1 オペランドの NaN を静止化して返す。ARM はオペランドの優先順位で選び、既定 NaN モードでは常に既定の NaN を返す。RISC-V は常に正準 NaN を返す |
| NaN の符号化 | MIPS の旧来の符号化と PA-RISC は、仮数部の最上位ビットが 1 のものを通知型 NaN とする（IEEE 754-2008 と逆） |
| 非正規化数の扱い | x86 の FTZ と DAZ、ARM の FZ、SuperH の DN |
| 精度の制御 | x87 の精度制御（仮数部を 24、53、64 ビットに丸める） |
| 例外フラグの種類 | IEEE の 5 種に加え、x86 の非正規化オペランド、Power の無効演算の細分類（VXSNAN、VXISI など） |

例外フラグを得た後で、例外のトラップを起こすか、累積フラグに足すかは、ゲスト ISA の意味論が決める。

## x87 と 68881 の拡張精度

x87 の 80 ビット形式は、整数ビットを明示的に持つので、IEEE の形式にない値（擬似非正規化数、非正規化されていない数、擬似 NaN、擬似無限大）が存在する。これらの値の扱いは 8087、80287 と 80387 以降で異なり、80387 以降の多くは無効なオペランドとして扱う。この違いは挙動パラメータとして x86 の CPU モデルに持たせる。68881 の拡張精度も整数ビットを明示的に持ち、非正規化されていない数を受け付けるので、同じ仕組みで扱う。

x87 の超越関数命令（`FSIN`、`FPATAN`、`F2XM1`、`FYL2X` など）の結果は、CPU の世代ごとの内部実装に依存し、ビット単位の結果は公開されていない。polyisa は、十分な精度で計算してから 80 ビットに丸めた値を返し、実機との最終ビットの差は再現しない。テストでは、これらの命令の結果を許容誤差つきで比較する。

初期の Pentium の `FDIV` の誤りのように、特定の CPU モデルの既知の誤動作は、再現の手順が公開資料で確定している場合に限り、挙動パラメータとして再現する。

## 十進演算

`decimal` クレートは、二つの十進演算を提供する。

一つはパック十進整数（BCD）の演算である。VAX の `ADDP4` や `EDITPC` などのパック十進命令、s390 系の `AP`、`ZAP`、`ED`、x87 の `FBLD`/`FBSTP`、68k の `ABCD`/`SBCD`/`PACK`/`UNPK`、Power の `bcdadd.` が使う。無効な数字や符号の扱いと、結果の符号の正規化の規則は ISA ごとに異なるので、浮動小数点と同じく環境として渡す。

もう一つは IEEE 754 の十進浮動小数点である。Power と s390 系は DPD 符号化を使うので、DPD 符号化を扱う。BID 符号化を使うハードウェアの命令は対象の ISA にないので、扱わない。

## 検証

二進の IEEE 形式と x87 拡張精度の演算は、Berkeley TestFloat が生成するテストベクタと比較する。TestFloat は、丸めモードとアンダーフローの判定時期を指定してベクタを生成できるので、`FpEnv` の組み合わせごとに検証できる。TestFloat は外部のツールとして別に用意し、生成したベクタはリポジトリに含めない（[検証戦略](testing.md)）。

NaN の伝播規則は ISA ごとの規定であり、TestFloat の検証範囲の外にある。ISA の仕様書の規定から、NaN のオペランドの組み合わせごとのテストを書く。16 進浮動小数点、DEC の形式、十進演算は、仕様書の例と、十進演算については公開されている十進演算のテストケース集を使う。

## 性能

ソフトウェアによる計算はホストの FPU より遅い。高速化として、丸めモードが最近接偶数で、入力と結果が正規化数であり、例外フラグの計算が不要か安価に求まる場合に限って、ホストの浮動小数点演算を使う経路を後から追加する。この経路は、ソフトウェアの経路と結果がビット単位で一致する条件でだけ使い、両経路の差分テストで一致を確認する。

WebAssembly の浮動小数点演算は、丸めモードが固定で例外フラグを持たないので、この高速経路の対象になりやすい。ただし、WebAssembly は NaN の値を非決定的と定めているので、決定性を保つため、polyisa は常に正準 NaN を返す。
