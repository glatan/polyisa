# x86

## 概要と対応範囲

16 ビット（8088〜80286）、32 ビット（80386〜Pentium III・generic32）、64 ビット（x86-64 v1〜v4）を単一クレート `guests/x86` で扱う。ユーザーモード命令として整数・x87・MMX・3DNow!・SSE〜SSE4.2・AVX/AVX2・AVX-512・AVX10・AMX・APX（REX2/EGPR）・CET・PKU・WAITPKG・FSGSBASE・TSX 等を対象とする。

- **CPU モデル**：実モード系は `i8088`、`i186`、`i286`、`i386`、`i486`、`pentium`、`pentium_mmx`、`pentium_pro`、`pentium_ii`、`pentium_iii`、`pentium4`、`pentium4_prescott`、`core2`、`penryn`、`nehalem`、`westmere`、`sandy_bridge`、`ivy_bridge`、`haswell`、`broadwell`、`skylake`、`skylake_x`、`ice_lake`、`tiger_lake`、`sapphire_rapids`、AMD 系は `k6`、`k6_2`、`athlon`、`athlon_xp`、`athlon64`、`phenom`、`phenom_ii`、`bulldozer`、`piledriver`、`zen`、`zen2`、`zen3`、`zen4`、`zen5`、汎用は `generic32`、`x86_64`、`x86_64_v2`、`x86_64_v3`、`x86_64_v4`（計 44 モデル）。
  世代モデルの機能構成と CPUID 署名は代表的な構成への近似であり、stepping ごとの差異や OEM 版の差は網羅していない。
- **実行モード**：`x86map.rs` で `m64`/`o16`/`o32`/`a16`/`a32`/`a64` を宣言している。実モード実行（`run_m16`）は map 経路でセグメント基底（`selector << 4`）・16 ビット SP・`CS:IP` フェッチを処理する。
- **識別情報**：機能集合から `IDENT_BITS` 経由で CPUID リーフを導出する（`cpuid::derive`）。
- **挙動パラメータ**：`bsf_zero_input`（BSF/BSR の入力 0 時の宛先動作）などを `Model::param` で定義している。

## 対応する OS・ABI と実行環境

- **Linux（`os-linux::x86`）**：`x86_64`、`i386`（x86-32）、`x32`（ILP32）の 3 ABI。マルチプロセス・マルチスレッド（`clone`/`fork`/`execve`/`wait4`/`futex`）、`os-linux::sock`・`os-linux::wait`、`kernel::HostIo` 非同期待ち、x86-64 vsyscall ページ、x86-64/i386 の自分宛てシグナル配送（rt フレーム）、CPU 例外からの同期シグナル変換、AMX 利用許可（`arch_prctl`）を実装している。
- **JIT**：`crates/cli/src/run_x86.rs` が `POLYISA_JIT` で x86-64 ホスト JIT に対応している。
- **タイミング**：8088 専用モデル（`timing::I8088`：4 バイトプリフェッチキュー＋BIU バス占有の T-state モデル）、80486・Pentium の `exact` 表を持つ。

## 実装の構造と特記事項

仕様記述は `guests/x86/spec/x86min.rs`（初期の変形列挙経路）、`x86map.rs`（オペコード表 `map`・`0F`/`0F 38`/`0F 3A`・VEX/EVEX/REX2・APX 経路）、`x86cpu.rs`（機能・モデル・識別情報）の 3 ファイルに分かれている。`x86min` 側の命令長判定（`fetch_len`）とオペランド展開（`dispatch`）は `crates/cli/src/run_x86.rs` に残っている。条件フラグは遅延評価で管理し、TSX のトランザクション開始は仕様の許容範囲として常に失敗を返す。

map 経路でデコードできる命令はすべて実行ディスパッチまたはインタプリタ層の具体値実行へ接続している。CPL0/SMM/VMX/SMX を必要とする命令は、ユーザーモードでは #GP/#UD 相当の例外として扱い、実モードではキャッシュ制御を no-op・MSR を最小近似で扱う。CPUID は leaf 7 subleaf 1 の機能ビットも導出する。XSAVE/XRSTOR は実機の標準レイアウトで AVX-512（opmask・ZMM_Hi256・Hi16_ZMM）、AMX（XTILECFG/XTILEDATA）、APX EGPR（成分19）を扱い、XSAVEC の圧縮レイアウト保存と XRSTOR での復元にも対応する。XSAVES/XRSTORS は CPL0 専用なので Linux ユーザーモード実行の対象外とする。APX は昇格 ALU/シフト/INC/DEC/NOT/NEG/IMUL/PUSH2/POP2 に加え、CCMPscc/CTESTscc の dfv/scc 解釈と SETcc/IMUL 即値形の zero-upper 選択、CMOVcc の NDD 形、CFCMOVcc のフォールト抑制・条件付きストアを実装している。REX2/EVEX.map4 の APX 形は XCR0[19]=1 を要求し、Linux ユーザーモードの初期 XCR0 には APX 対応モデルでこのビットを立てる。

## 既知の簡略化と未対応範囲

- **世代モデルの近似**：`pentium` は P54C（MMX なし）、`pentium_mmx` は P55C、`pentium_pro` は MMX を持たない構成に修正済み。ただし挙動パラメータ（`stack_wrap` など）は i386 系の SST 実測に基づく近似値を世代横断で継承しており、486 以降の世代で同じ値とは検証されていない。
- **旧列挙経路と PC 幅**：旧 `x86min` 経路は `is64` 真偽値でモードを持ち、`CpuState.eip` が `u32` のため x86-64 の上位 32 ビット PC を保持しない箇所が残る。
- **`statfs` 系 syscall**：`x86_64`（137/138）と `i386`（99/100/268/269）は番号表のみで分岐を持たず `ENOSYS` を返す（BusyBox の `df` は失敗扱い）。
- **x87 の機能ゲートと近似**：
  - ESC（`D8`–`DF`）は 8088 の無視動作を壊さないため `fpu` 機能でゲートしていない。世代ごとの ESC 扱い（8088 無視、486SX INT 7 等）の意味論分岐は未実装。
  - 超越関数（`FSIN`/`FCOS`/`FSINCOS`/`FPTAN`/`FPATAN`/`FYL2X`/`FYL2XP1`/`F2XM1`）はインタプリタ層で host `f64` を使う近似として実装した。拡張精度の 64 ビット仮数・大角度減算の bit 正確性は持たない。無効演算と 0 除算では x87 の IE/ZE を sticky に立て、マスクなしでは ES/B も立てるが、次の x87 命令での遅延 #MF 配送は未実装。`FCLEX` は例外状態をクリアする。`FISTTP` は FCW に関係なく切り捨てる。`FPREM`/`FPREM1` は倍精度経由の完全減算近似（`C2=0` 固定）、`FSCALE` は指数加算の飽和近似、`FXAM` はタグ未モデルのため `0.0` と空スロットを区別しない。`FLDENV`/`FNSTENV` の FIP/FCS/FOP/FDP/FDS は 0 固定。
- **SSE4.2 / ROUND の近似**：`PCMPxSTRx` は `imm[1:0]` を無視して符号なしバイト要素固定で処理する。`ROUNDPS/PD/SS/SD` は丸め指定ビットを受理するが MXCSR の例外マスク・フラグ更新は行わない。
- **USER_MSR / XSTORE の近似**：`URDMSR` は公開ユーザー MSR の実体を持たず 0 を返し、`UWRMSR` は uarch 制御なので no-op とする。USER_MSR enable ビットと MSR bitmap による #GP/#UD 判定は未実装。`XSTORE`/`REP XSTORE` は PadLock RNG の deterministic な近似で、品質ビットに応じたバイト数を返す。REP 形は quality ごとの 8/4/2/1 バイトを 1 回分として生成し、各回を 8 または 4 バイトの store で書くため、要求数を最大 7 バイト超えて書く。RNG control MSR のステータスビットはモデル化しない。
- **JIT と命令デコーダ**：JIT は legacy decoder を使い、map decoder とは LOCK 接頭辞・世代ゲート・特権命令の判定が完全には共有されていない。通常の Linux ユーザーモード命令では同一結果を狙うが、無効 LOCK や新規 system 命令では解釈が分かれ得る。例外配送そのものは GAP-0026 の課題である。
- **デコード差分と接頭辞受理**：
  - `heavy_oracle_llvm` 既知差分（`KNOWN`）：メモリ専用命令（`movbe` 等）の `mod=11` 受理、x87 `mod=11` 未定義スロット受理、旧列挙経路での必須接頭辞なし形受理。llvm-mc が冗長な 66/F2/F3 接頭辞を無視して受理する差分はオラクル側の寛容さとして残る。
  - `RDPKRU`/`WRPKRU`・`XGETBV`/`XSETBV`・`CLDEMOTE`・`FXSAVE`/`XSAVE`・`CLFLUSH` の接頭辞受理条件は Intel SDM の例外表との照合が残る。
- **8088 タイミングの対象範囲**：`heavy_timing_8088` の SST CYCL 一致対象は「バスアクセスなし・キューフラッシュなし」の形に限る。スタック・メモリアクセスを伴う形、分岐成立によるキューフラッシュ、`modrm + imm` 形、`cwd`/`aaa` 等の ±1 揺れ、`REP`・文字列命令は対象外。
- **i386 BusyBox**：`heavy_program_i386_applet_probe` で整数命令の欠落は解消済み。未到達アプレットは x87 FPU と実行時間制限のみ。

## 検証手段

- **OS なし・単体**：`bare_x86min`、`bare_x86run`、`bare_x86hello`、`bare_x86file`、`bare_x86ext`
- **適合テスト**：`heavy_conformance_sst8088`、`heavy_conformance_sst80286`、`heavy_conformance_sst80386`
- **デコーダオラクル**：`heavy_oracle_llvm`、`heavy_oracle_xed`
- **実行差分**：`heavy_diff_host`（ホスト x86-64 CPU）、`heavy_diff_sde`（Intel SDE）
- **ABI・プログラム・JIT**：`heavy_abi_uapi`、`heavy_program_busybox`、`heavy_program_busybox_i386`、`heavy_program_i386_applet_probe`、`heavy_program_x32`、`heavy_program_x86ext`、`heavy_program_net`、`heavy_jit_diff`
- **タイミング**：`heavy_timing_8088`、`heavy_timing_i486`、`heavy_timing_pentium`
